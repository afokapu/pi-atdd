### Extraction discipline

Use `Domain of Control → Clarifier → OoC-in-domain` as *source elicitation stages*, with a **separate state-bearing lens**, not new O1–O8 admission gates (ATD-26, accepted Storymaker extraction ADR). Distinguish governed state from an event, action, policy, actor, artifact instance, current value, direction and output assertion. State is *direction-neutral*, Resource is a **bearer class**, and cited use must be real. The same source rule can evidence several candidate states and several rules can support one candidate; multiple bearers or independently changing state aspects must not be silently collapsed. Direct actuation, if any, is a **situated** later Capability/authority/Resource/Situation/possible Driver question, not an OoC admission criterion.

Neither the rule node, an edited YAML file, nor the proposal action/event is, on that evidence alone, a reusable direction-neutral state OoC. This is **not** a claim that future work cannot extract a separate state subject from stronger evidence.
- **NC-02:** A read-only investigation has no tracker issue obligation under both local tracker source statements. Lack of an issue on such work is **not** failed traceability.
- **NC-03:** GET/HEAD routes do not trigger mutating-route guard matching; a bare token `DELETE` in prose or an unrelated object is not proof of an observed Bun route construct.
- **NC-04:** An acceptance/test header can be syntactically present but non-verifiable or behaviorally unrelated; a static header success does **not** certify test truthfulness or delivered behavior.
- **NC-05:** A JS-only Bun app is outside the typecheck-enforcement rule's scope; a `tsconfig` extending unknown base configuration is *not* proof strictness is disabled.
