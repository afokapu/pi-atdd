Title: Name artifacts as theme(:category)*:aspect(.variant)?
Given: An artifact name is being written, changed, or referenced in any document (e.g. a plan, wagon, WMBT, acceptance, contract, or doc — non-exhaustive).
When: The planner writes that artifact name or a reference to it.
Then: Write the name as {theme}(:{category})*:{aspect}(.{variant})? — exactly one theme, zero or more hierarchy categories, exactly one leaf aspect, and an optional variant, every part kebab-case.
Prefer:
- Start with the top-level architectural theme as the namespace (kebab-case ^[a-z][a-z0-9-]*$).
- Use colons only for hierarchy (vertical depth): each category navigates one level down the resource tree; depth is unlimited.
- End the colon path with the leaf resource noun as the aspect.
- Use a single dot only for a variant: a lateral variation, facet, or state of the aspect (typically at most one).
- Use the simple form theme:aspect when no hierarchy is needed.
Avoid:
- Omitting the theme or the aspect, or naming with more than one theme or aspect.
- Using a dot for hierarchy or a colon for a variant.
- Non-kebab-case parts (uppercase, underscores, leading digits or hyphens).
Why: Theme-based namespacing gives semantic clarity and collision-free names, colons give unlimited hierarchical depth and dots lateral variants, and the structure keeps artifact names aligned with contract file paths.
