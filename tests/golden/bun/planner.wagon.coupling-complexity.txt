Title: Report each wagon's coupling complexity and flag those above the soft threshold
Given: A plan whose wagons declare produce/consume artifacts, forming a directed wagon graph keyed on artifact NAMES.
When: You plan or validate the plan (`atdd validate planner`), including unchanged plans and threshold-only config changes.
Then: Report every wagon's coupling complexity (fan_in x fan_out over the produce->consume name graph) and flag, as advisory and non-blocking, each wagon above the soft threshold planner.wagon.coupling_complexity_threshold (default 6).
Prefer:
- Run `atdd validate planner` so each wagon's complexity is visible while planning.
- fan_in = wagons consumed from; fan_out = wagons consuming its outputs; reason on the product (Henry-Kafura).
- Optionally review flagged wagons' separability.
Avoid:
- Blocking or halting planning on the advisory.
- Keying coupling on the nullable contract field instead of artifact names.
- Renaming/merging artifact names only to lower the product.
Why: High fan_in x fan_out marks an entangled wagon that hurts separability; non-blocking reporting keeps complexity visible until the threshold is calibrated.
