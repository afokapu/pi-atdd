Title: Bind every required telemetry item to its emitting source
Given: An acceptance in the repository (changed or not) has telemetry disposition required and lists a resolvable concrete telemetry URN (a required item)
When: the repository's acceptances and non-test source are in that state, regardless of which files the current change touches
Then: Bind the required item to at least one non-test implementation source file with a `// Telemetry: <urn>` header that resolves to it.
Prefer:
- Put the header `// Telemetry: <urn>` (the required item's exact URN) in the non-test source file that actually emits the item; the header must resolve the way coder.bun.telemetry-source-binding defines — fix resolution failures under that rule.
- If nothing emits the item, drop the requirement from the acceptance instead of inventing a binding.
Avoid:
- Binding the required item only from a test file — test headers do not count as implementation.
- Adding a `// Telemetry:` header to source that does not emit the item just to silence the finding.
- Leaving a required item no source claims: telemetry the plan believes in and the code has never heard of.
Unless:
- The repository has not yet adopted the telemetry rule family — the rule is inert until adoption, like every rule in this family.
Why: Traceability needs all three legs — planned, implemented, tested; this rule closes the implemented leg so a required item is never planned yet unemitted.
