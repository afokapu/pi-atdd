Title: Bind the plan decomposition to a local ATDD issue before Ratify
Given: An atdd plan session has a decomposition. It may have started with no pre-existing issue or brief.
When: You Ratify (confirm/lock) the decomposition and author the plan.
Then: Before confirm, bind the decomposition to a local ATDD issue record (a target issue's manifest/State Store slug, or one minted from the main job), then author the plan as that issue's PLANNED-phase substrate on its registered branch + worktree.
Prefer:
- Start conversationally and decompose before any issue paperwork; no pre-existing issue or brief is needed. Bind any time before confirm.
- `atdd plan session bind-issue --id <sess> --issue <slug>`; list bindable slugs with `atdd coach issues open`, or mint one from the main job.
- Bind by the local manifest/State Store slug; the GitHub number is a synced projection added later.
Avoid:
- Reading 'no up-front ceremony' as 'no issue at all'. The session removes the ceremony, not the issue.
- Confirming an unbound decomposition, or authoring plan substrate on an untracked branch (no issue + branch + worktree).
- Waiting for, or binding by, a GitHub issue number.
Why: The iron rule (issue + branch + worktree per repo modification) must always hold, even with no GitHub, so plan substrate always lands on a tracked branch tied to a local issue.
