Title: Test that each declared train runs its declared wagon sequence, in order
Given: A consumer declares an interlocking route space and a train with an ordered wagon `sequence:` is reachable from a declared route
When: the suite contains no test comparing that train's executed steps to its declared sequence in order (a standing condition, whatever the current change)
Then: Some test MUST assert that the ordered steps the TrainRunner reports executing equal the train's declared wagon sequence, in order — not merely which train was selected.
Prefer:
- Run the train through the real TrainRunner, read the expected order FROM the train's `sequence:` (wagon names), assert executed steps equal it in order.
- Pair it with a runtime that reads the plan: the coder rule makes the runtime READ it, this makes the suite prove it OBEYS it; worthless apart.
Avoid:
- Counting route-coverage/trace-binding tests: they prove WHICH train, not WHAT it ran.
- Restating the expected sequence as literals: tracks a copy, not the declaration.
- Asserting a sequence against a runtime that hardcodes it: proves only self-consistent hardcoding.
- Set-membership or length-only checks.
Unless:
- The consumer declares no interlocking route space.
- The train is reachable by no declared route; the rule follows the route space.
Why: A runtime that reads the plan but is never tested can drift: the plan is edited, the runtime dutifully runs the new sequence, and no test notices because none asserted what ran (a whole replaced `sequence:` left a suite green). Both halves are needed before 'the train YAML is the source of truth' is checkable, not a slogan.
