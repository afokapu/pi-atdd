Title: Make each wagon's capability boundary legible from its description
Given: Any wagon in the plan, whether newly added, changed, or existing and unchanged
When: the planner writes, updates, or reviews that wagon's description
Then: The description alone must make the wagon's capability boundary (what it does and does not own) understandable later without the original conversation.
Prefer:
- Write the description so a later reader can understand, from it alone, what the wagon does and does not own.
- Put the rationale in the existing wagon schema description field.
Avoid:
- Introducing a new schema field (e.g. a separate rationale field) to carry the boundary or rationale.
- Descriptions that only make sense with the planning conversation in hand (references to 'as discussed', unstated context).
Why: Wagons outlive the conversation that created them, so a later reader must be able to tell from the description alone what the wagon owns and does not own. Reusing the existing description field keeps the schema unchanged.
