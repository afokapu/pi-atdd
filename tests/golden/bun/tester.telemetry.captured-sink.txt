Title: Assert telemetry tests on a captured sink, not on a return value
Given: A telemetry test: a test file with a `Telemetry:` header, a TELEMETRY/EVENT/METRIC URN kind segment, or *.telemetry.test.* colocation
When: the test is written or changed
Then: The test asserts on the emission itself via the captured sink — `toHaveBeenCalled[With|Times]` or an expectation on `.emit` / `.emitted` / `.capture` / `.track` / `.record`.
Prefer:
- Capture the emitter (spy, mock, or captured array the emitter writes to — the thing whose content is the emission), inject it into the unit under test, and assert on it.
- Assert the exact event identity and payload on the sink (e.g. toHaveBeenCalledWith(<event URN>, <payload>)), joining the captured-sink and exact-identity requirements.
Avoid:
- Asserting only on the function's return value — a return value is not a sink; it proves the function ran, not that the item fired.
- Satisfying the detector with an emission-vocabulary expectation that does not inspect what the sink actually received.
Unless:
- The test is not telemetry-identified; only telemetry-identified tests are scanned and the tester profile's own rule governs the rest.
- The rule family has not been adopted in the repository (inert until adoption, like every rule in this family).
Why: Dashboards, alerts and downstream analytics are built on the emission; a return-value check proves the function ran, not that the event fired — only the sink saw it fire.
