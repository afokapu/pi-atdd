Title: Keep the journey view generated from plan/ and current
Given: The repository has a docs/ directory and its plan/ declares at least one journey or interlocking.
When: You finish any plan work or review in that repository, whether or not you touched plan/ or docs/; pre-existing drift and renderer upgrades count.
Then: docs/purpose/journeys/ must contain exactly, byte-for-byte, what `atdd-bun docs journeys` generates from the current plan/: index.adoc plus one SVG per journey map, per journey's nominal path, and per routed train.
Prefer:
- Regenerate and commit: `bun run atdd-bun docs journeys`.
- Fix what the view shows in the plan, then regenerate.
- If index.adoc there is hand-written, move its content elsewhere first (the generator refuses to overwrite it without --force).
- Keep the gaps table (unreached interlockings, open routes, unrouted trains) visible and accurately rendered; it is part of the contract.
Avoid:
- Hand-editing or adding files under docs/purpose/journeys/; change the plan, never the generated files.
- Leaving the view missing or stale, or keeping files the generator does not produce.
- Skipping the page when the plan has interlockings but no journey; it shows every interlocking as unreached.
- Treating the view as acceptance evidence; it renders planned behaviour only.
Unless:
- The repository has no docs/ directory.
- The plan declares no journey and no interlocking.
Why: A hand-drawn journey page drifts from the plan the moment either changes; generating it and failing on any difference keeps documented journeys equal to planned ones and lets reviewers judge a decomposition without reading interlocking YAML.
