Title: Define each feature as the smallest independently-verifiable slice of one wagon's behavior
Given: A planner is authoring, editing or reviewing a feature within a wagon
When: the feature's scope, boundaries or any of its facets (shape, wagon link, feedback loop, size) are written, changed or checked
Then: Keep the feature the smallest independently-verifiable slice of exactly one wagon's behavior: a bounded capability that is well-shaped, wagon-linked, feedback-closing and size-bounded.
Prefer:
- Declare a URN, a status and a non-empty acceptance section on every feature (planner.feature.shape).
- Link each feature to exactly one wagon (planner.feature.wagon-link).
- Make the feature close the feedback loop it opens (planner.feature.feedback-loop-close-the-loop).
- Keep the feature within the hard limits and the size-max rule (planner.feature.hard-limits, planner.feature.size-max-rule).
Avoid:
- Features that cannot be verified on their own or bundle several capabilities.
- Features shared across wagons or with no wagon.
- Features with an empty acceptance section, missing URN or missing status.
- Features that open a loop without closing it, or exceed size limits.
Why: A stable meaning of 'feature' keeps planning slices independently verifiable and bounded; this node is an advisory semantic anchor that enforces nothing directly — its enforceable parts live in the constraint/rule nodes that require it.
