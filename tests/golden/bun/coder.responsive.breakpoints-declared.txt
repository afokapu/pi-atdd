Title: Media queries use only the declared breakpoints
Given: A stylesheet or component style outside vendored/generated trees contains an `@media` width condition (`min-width`/`max-width` or range syntax such as `width >= 768px`, `768px <= width`). Term frontend_settings: `atdd-bun.yaml` → `frontend.breakpoints` (the widths media queries may use) and `frontend.viewports` (the widths responsive specs render at; the smallest bounds fixed widths).
When: Any media-query width condition in scope exists or is added/changed, or `frontend.breakpoints` is edited so existing conditions must be re-checked.
Then: Every width in every such condition MUST be one of the breakpoints declared under `frontend.breakpoints` in `atdd-bun.yaml` (default 480, 768, 1024, 1280); a `max-width` within 1px below a breakpoint (`767px`, `767.98px`) counts as that breakpoint, and `em`/`rem` convert to px at 16px.
Prefer:
- During GREEN: reuse an existing declared breakpoint that expresses the required layout transition.
- During GREEN: add one breakpoint to `frontend.breakpoints` only when the current design genuinely requires a distinct transition width.
- During GREEN: change only the affected media query or configuration entry.
Avoid:
- Using an undeclared one-off width as a shortcut.
- Adding speculative breakpoints for future devices.
- Normalizing unrelated responsive rules while fixing this one.
Unless:
- The file lives in a vendored or generated tree (`node_modules`, `dist`, `build`, `_generated`); these are never scanned.
Why: CSS custom properties cannot be used in media queries, so breakpoints cannot be tokens; declaring them once and requiring every query to use them keeps layouts switching at the same widths everywhere instead of at a new one per component.
