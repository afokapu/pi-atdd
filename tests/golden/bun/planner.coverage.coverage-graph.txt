Title: Keep plans traceable from train to acceptance test criteria
Given: You are authoring or changing planning artifacts (trains, wagons, features, WMBTs, acceptances), including acceptance test criteria.
When: You create, edit, move or delete any artifact in the hierarchy, its containment links, or an acceptance's test criteria.
Then: Keep the plan traceable along Train -> Wagon -> Feature -> WMBT -> Acceptance -> Test criteria, each level contained by its parent and guarded by its coverage validators; from Phase 2 (PLANNER_TESTER_ENFORCEMENT) those validators are strict, so their findings block the plan.
Prefer:
- Register each wagon in a train's participants (COVERAGE-PLAN-2.1).
- List each feature in its wagon's features[] (2.1, 2.2).
- List each WMBT in its feature's wmbts[] (2.2, 2.3).
- Link each WMBT's acceptances via acceptances[] and give each acceptance test criteria (2.3, 2.4).
- Before handing off, run the coverage validators along the whole chain of every artifact you changed — its ancestors up to the train and its descendants down to test criteria, not only the level you edited.
- Check the project's active rollout phase before deciding whether findings block; if you cannot establish it, report the phase as unknown rather than assuming findings are non-blocking.
Avoid:
- Orphan artifacts that no parent level contains.
- Fixing a validator finding by adding placeholder links or empty acceptances instead of real coverage.
Why: Coverage only means something if every acceptance traces up to a train and down to test criteria; each level is guarded by validators so gaps surface during planning (ATDD Hierarchy Coverage Spec v0.1, section 2), strictly from Phase 2.
