Title: Set feature size to max(WMBT size, Footprint size) and split features over limits
Given: Any feature plan (new or existing, with or without complete size, covers_wmbts and footprint fields)
When: The planner creates, edits (including prose-only) or validates that feature plan
Then: Ensure the feature's size field is present and equals exactly max(WMBT size, Footprint size), with the WMBT bracket from covers_wmbts and the Footprint size from the footprint point score.
Prefer:
- Derive the WMBT size bracket from covers_wmbts and score the footprint with the point system (defined in planner.feature.size-max-rule); take the larger.
- Split a feature whose footprint exceeds component/event limits; always split one exceeding hard limits (tables/jobs/integrations); limit values come from planner.feature.hard-limits.
- If covers_wmbts or footprint is missing, fill it in from the feature's scope before setting size; do not guess a size without both inputs.
Avoid:
- A size differing from max(WMBT size, Footprint size), e.g. using only one of the two.
- Leaving an over-limit feature unsplit, even when only editing its prose.
- Trimming covers_wmbts or under-reporting footprint to lower size or dodge a limit.
Why: The convention defines feature size as the larger of the WMBT bracket and the footprint's architectural-complexity score, and requires features over component/event or hard limits to be split.
