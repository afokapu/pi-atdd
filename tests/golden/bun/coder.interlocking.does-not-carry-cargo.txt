Title: Keep Cargo out of the InterlockingRunner (Bun)
Given: A Bun module under src/trains/** that defines an InterlockingRunner (not the production TrainRunner module)
When: the module is created or changed
Then: Keep Cargo inside TrainRunner execution: the InterlockingRunner must not reference, mutate, store (artifact_urn -> artifact_data) or route on Cargo.
Prefer:
- InterlockingRunner reads only initial action/inputs/state before execution and a completed TrainResult at a declared route boundary.
- Leave Cargo to TrainRunner, which passes it between wagons; wagons read and return artifact objects.
Avoid:
- Cargo references or `cargo[...] = ...` in an InterlockingRunner module.
- Storing artifact_urn -> artifact_data runtime values in the interlocking.
- Routing on mid-train Cargo state; letting Cargo select train variants.
Unless:
- The production TrainRunner module legitimately constructs and carries Cargo; it is not scanned for Cargo bleed.
Why: Cargo is the artifact data plane carried by TrainRunner between wagons inside a selected train; the cargo_boundary keeps it inside that execution, so the interlocking never routes on mid-train Cargo state nor lets Cargo select train variants, routing only on initial inputs and declared-boundary TrainResults.
