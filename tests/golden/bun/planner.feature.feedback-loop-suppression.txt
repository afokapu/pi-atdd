Title: Suppress close-the-loop for docs-only feedback-loop features only via the inline kind-line marker
Given: A feature declared `kind: feedback-loop` whose deliverable is documentation only
When: the planner wants to opt the feature out of the close-the-loop rule
Then: Write the suppression inline on the kind: line exactly as `kind: feedback-loop  # atdd:suppress(planner.smoke.feedback-loop-close-the-loop) UNTIL=YYYY-MM-DD`.
Prefer:
- Use the suppression marker (the inline opt-out for docs-only feedback-loop features) with a concrete UNTIL date so the relief expires.
Avoid:
- Suppressing close-the-loop on a feedback-loop feature that is not docs-only.
- Placing the suppression anywhere other than the kind: line, or omitting the rule id or UNTIL date.
Why: Docs-only feedback-loop features have no runtime loop to close, so a dated, inline, rule-specific opt-out is the sanctioned hatch that keeps the relief visible and time-bounded.
