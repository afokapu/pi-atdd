Title: Report verb-object naming drift across the existing wagon/feature corpus without blocking
Given: A CONFIRM run with wagon and feature artifacts on disk (whatever their history or conformance)
When: The corpus naming check scans those names, or the planner reads its drift report
Then: Report every non-conforming wagon/feature name (artifact kind, slug, reason) with a total count, as advisory only — never block on it.
Prefer:
- Treat the count as the signal: a rising count means new drift entered outside the authoring gate — the only actionable part; a falling count means debt was paid opportunistically.
Avoid:
- Widening the verb lexicon to clear the report — it silences a rule that correctly describes the corpus.
- Turning the report into a blocking gate or failing a plan because the count is non-zero.
Why: Authoring gates read only the session's kept units, so hand-renamed or out-of-session artifacts drift unnoticed; the count makes drift visible. It stays advisory because renaming is unaffordable, and a blocking rule with no affordable remedy gets ignored.
