Title: Back every interlocking payload contract with a schema body
Given: An interlocking whose messages reference payload contract identities (any interlocking, regardless of author or whether the reference changed).
When: The interlocking is validated at CONFIRM, where this check is confirm-blocking.
Then: Ensure every payload contract identity referenced by an interlocking message resolves to a contract schema body on disk.
Prefer:
- Plan the contract schema body at its expected schema path alongside the interlocking message that references the contract, so the reference resolves before CONFIRM.
Avoid:
- Referencing a payload contract identity in an interlocking message that has no schema body on disk (a name-only contract).
- Treating an existing file at the expected path as sufficient when it does not hold the contract's schema body.
- Silencing the finding by removing or loosening the payload contract reference instead of providing the schema body.
Why: An interlocking message is only a usable contract if its payload identity resolves to a concrete schema body; a dangling contract reference cannot be validated or implemented against.
