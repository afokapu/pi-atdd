Title: Compute a feature's footprint points as the ceiling of summed component weights
Given: A feature's components are known, each with a stack (backend/frontend), a layer, a granular component type from the coder conventions, and a count.
When: The planner computes or revises the feature's architectural footprint.
Then: Footprint points = sum(count × weight[stack][layer][type]), rounded UP (ceiling), using the weights below.
Prefer:
- Weights are listed per stack × layer × component type, verbatim. The same type can weigh differently by stack, e.g. controllers are 1 in backend.presentation and 2 in frontend.presentation.
- backend.presentation: controllers 1, routes 0, serializers 0.5, validators 0.5, middleware 1, guards 1, views 1.
- backend.application: use_cases 2, handlers 1, ports 0, dtos 0, policies 1, workflows 2.
- backend.domain: entities 1, value_objects 0.5, aggregates 2, services 1, specifications 0.5, events 0, exceptions 0.
- backend.integration: repositories 2, clients 1, caches 0.5, engines 3, formatters 1, notifiers 1, queues 2, stores 1, mappers 0.5, schedulers 2, monitors 1.
- frontend.presentation: views 1, components 0.5, containers 1, controllers 2, routes 0, layouts 1, styles 0, animations 0.5, forms 1, hooks 0.5, directives 0.5, filters 0.5.
- frontend.application: use_cases 2, ports 0, policies 1, dtos 0.
- frontend.domain: entities 1, value_objects 0.5, services 1, specifications 0.5, exceptions 0.
- frontend.integration: repositories 2, clients 1, stores 1, serializers 0.5, mappers 0.5, interceptors 1, caches 0.5, synchronizers 2, monitors 1, validators 0.5, workers 2, connectors 1.
- Weights follow the universal 0–3 complexity scale: 0 = pure config/declaration (routes, dtos, events, ports, styles); 0.5 = simple transformation/validation (serializers, mappers, validators, hooks, filters); 1 = single-responsibility business logic (controllers, services, clients, views); 2 = complex orchestration/state/persistence (use_cases, repositories, queues, workflows); 3 = very complex algorithms/integrations (engines with ML/graph/optimization).
Avoid:
- Rounding down, rounding to nearest, or leaving fractions (3.5 must become 4).
- Estimating points by feel instead of summing the weights.
- Retyping or omitting weighted components to lower the score.
Why: Summing type weights makes a feature's size reproducible from its component inventory.
