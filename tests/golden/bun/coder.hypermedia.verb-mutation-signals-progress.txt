Title: Make every mutating htmx request signal that it is in flight
Given: An element issues a mutating htmx request (hx-post, hx-put, hx-patch or hx-delete), which changes server state so a duplicate is not harmless.
When: That element exists in the markup.
Then: The element issuing the mutation declares a progress signal: hx-indicator or hx-disabled-elt (either satisfies; both is fine).
Prefer:
- hx-disabled-elt (disables the control in flight, making double-submit impossible) where a duplicate is expensive, e.g. <form hx-post="…" hx-disabled-elt="find button">.
- hx-indicator (spinner region in flight) to show something is happening, e.g. <form hx-post="…" hx-indicator="#spinner">.
Avoid:
- <form hx-post="…">…</form> with no signal — invisible in flight.
- hx-indicator alone where duplicates are expensive: it says wait but does not stop the user.
- Treating a server idempotency key as an exemption: a real mitigation the rule cannot see.
- Adding indicators to hx-get elements under this rule — a UX preference, out of scope.
Unless:
- The element issues only hx-get (idempotent; a duplicate is harmless).
Why: htmx swaps fragments in place with no navigation, so the page looks identical while in flight; users correctly read 'nothing happened', click again, and a non-idempotent request runs twice (duplicate orders, charges, rows).
