Title: State the file's one job in a Purpose: line of at most 80 characters
Given: Any implementation (non-test) file in the codebase
When: its header is authored, changed, or checked
Then: The header carries a single `Purpose:` line of at most 80 characters that truthfully names the file's one job.
Prefer:
- During GREEN, derive the purpose from the responsibility introduced for the current acceptance.
- Use concrete responsibility language rather than implementation mechanics.
- If the purpose genuinely cannot fit because the new file owns multiple jobs, split only the responsibilities required by the current behavior.
Avoid:
- Inventing a vague purpose just to meet the length cap.
- Unrelated decomposition: when splitting a file whose purpose does not fit, do not decompose anything beyond the responsibilities the current behavior requires.
- Describing hypothetical future responsibilities.
- Multi-line or paragraph-length purpose descriptions.
Unless:
- The file is a test file (test files are excluded).
Why: An unbounded description becomes a paragraph that goes stale and, being believed, is worse than none; the 80-character cap forces naming one job, and a purpose that will not fit usually signals a file doing more than one thing (a design signal as much as a documentation rule).
