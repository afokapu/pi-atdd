Title: Name produce/consume artifacts by their nature: domain:activity-verb for events, domain:data-noun for state
Given: A wagon plan declares a produce block (artifacts the wagon creates and owns) or a consume block (artifacts it consumes).
When: The planner adds, renames, reviews or validates an artifact name there, or changes an artifact's nature (event vs state) or cardinality.
Then: Name it domain:activity-verb (past-tense verb) for a signal/event or domain:data-noun (noun/adjective) for state/data, plural for a collection.
Prefer:
- Produce entries: {name: 'domain:artifact-name', to: 'internal|external'} (visibility via 'to').
- Consume entries: {name: 'domain:artifact-name', from: 'wagon:slug|system:external|internal'}.
- Reuse the producer's exact name on every consume side.
- Adjective-like participles describing current state are valid state names (e.g. domain:chosen, domain:remaining); a dotted sub-path after the domain is allowed (e.g. domain:state.current).
Avoid:
- Present/imperative verbs for events; action-describing names for state/data; noun forms for signals.
- Singular names for collections; names lacking the 'domain:' prefix.
Why: Consistent naming makes an artifact's nature (event vs state vs collection) legible from its name alone, so consumers know whether they react to a signal or read data.
