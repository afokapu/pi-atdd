Title: Draw component events only from the owning feature's ioSeeds
Given: A component belonging to a feature declares consumed or produced events, or dependencies
When: the planner authors, edits or reviews those events or dependencies, or changes the feature's ioSeeds
Then: Every declared consumed event must come from feature.ioSeeds.consume and fit the component's role, and every declared produced event from feature.ioSeeds.produce and fit its capability, so all events are a subset of, and traceable to, a feature ioSeed.
Prefer:
- Need a new event? Add it to the feature's ioSeeds first, then reference it.
- Pick only the ioSeeds events the component's role actually consumes / its capability actually produces; the filter selects, it does not force inclusion of every seed.
Avoid:
- Inventing inputs/outputs the feature never declared (e.g. producing an event absent from ioSeeds.produce).
- Events not selected by the role (consume) or capability (produce) filter.
- More than 3 consumed or 3 produced events per component.
- Dependencies other than same-feature components or external dependencies.
Why: Limiting component events to the feature's ioSeeds keeps each component's interface within its feature's declared contract, so no component invents inputs or outputs the feature never promised.
