Title: SMOKE must drive the real entry point, not a synthetic fixture
Given: A SMOKE-phase test of the agent launch / production wiring is planned (plan, acceptance, WMBT), written or modified.
When: Choosing what the SMOKE test drives as its primary production wiring.
Then: The SMOKE test must drive the real CLI entry point (spawn, coach, or the rendered launch prompt), not a synthetic subprocess stub or fake multiplexer.
Prefer:
- Run the real CLI as a subprocess (subprocess.run([sys.executable, -m, atdd.cli, spawn, ...])) or use invoke_atdd_spawn, driving the real cmux-native launch path.
- Write agent scripts to tmp_path files.
Avoid:
- FakeMultiplexer as SMOKE wiring (bypasses real surface dispatch).
- Popen of cat, sleep or python -c as the agent command (pty wrapper / lifecycle only / bypasses adapter command construction).
- Agent scripts embedded as string constants (e.g. _SYNTHETIC_AGENT).
- Treating a green SMOKE suite as proof when it only proves the harness.
Unless:
- Inline '# atdd:suppress(planner.smoke.synthetic-fixture-bypass) UNTIL=YYYY-MM-DD'; the debt expires on that date.
Why: A stubbed SMOKE test proves the harness, not the product, and is green precisely where real wiring is untested. Incident #854: a Popen crash (missing shell=True on the adapter command tuple) stayed invisible because SMOKE used a Python stub.
