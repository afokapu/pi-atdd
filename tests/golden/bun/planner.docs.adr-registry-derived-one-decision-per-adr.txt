Title: One architectural decision lives in exactly one ADR file
Given: A docs corpus that records architectural decisions in docs/architecture/decisions
When: You plan, author or review an architectural decision, or review the ADR corpus
Then: Record each architectural decision in exactly one ADR file that declares :decides:. Do not split or duplicate it across ADR files, and do not put it in the registry.
Prefer:
- Write a new decision as its own `adr-YYYYMMDD-NNN-<slug>.adoc` with `:adr-id:`, `:status:`, `:date:` and `:decides:`, then regenerate the registry.
Avoid:
- Typing decision content into `decisions/index.adoc`. It belongs in an ADR file with a `:decides:` attribute. The registry holds references to decisions, never the decisions themselves.
Why: One decision in ONE ADR file is what makes the registry a navigable set with a single source of truth per decision (spec 2 §6). An exact, regenerated listing still cannot repair a decision scattered across files.
