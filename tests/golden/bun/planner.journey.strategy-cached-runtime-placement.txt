Title: Cached or incremental results: place cache work within implemented runtime
Given: Work reuses or incrementally recomputes an expensive, repeatable read or derivation with stable identities and tractable dependencies
When: deciding where the cache work or hit/miss routing runs
Then: Do not treat this pattern as providing a new runtime dispatch option, and do not plan on orchestration behavior inferred from it that is not implemented.
Prefer:
- Cache work can be internal to a wagon.
- An explicit hit/miss route can use an existing interlocking.
Avoid:
- Citing this pattern as providing or authorizing a new runtime dispatch option for cache hit/miss.
- Relying on unimplemented orchestration behavior inferred from this pattern.
Why: The pattern is guidance only; plans that assume dispatch or orchestration that does not exist cannot run.
