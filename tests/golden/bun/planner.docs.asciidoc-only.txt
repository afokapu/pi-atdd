Title: Author every file beneath docs/ as AsciiDoc (.adoc), never markdown
Given: A plan, wagon or doc change places an authored file beneath docs/ (any path not under docs/dist/).
When: The planner chooses the file's format or path.
Then: The file MUST be AsciiDoc (.adoc); an authored .md beneath docs/ outside docs/dist/ is a violation.
Prefer:
- Convert an existing docs/**/*.md to the same path with .adoc and keep its content intact.
- When converting a historical document, place it INTO docs/archive/ and set its :status: accordingly; migration preserves history and never promotes it to current.
- Decide by location only: under docs/, not under docs/dist/, ending .md → convert.
Avoid:
- Committing authored markdown anywhere beneath docs/ outside docs/dist/.
- Arguing a .md under docs/ is exempt because it is 'not really prose documentation' — the test is location, not content.
- Treating conversion to .adoc as making a historical document current.
- Expanding the plan to reject or convert README.md/CONTRIBUTING.md/root markdown under this rule; that belongs to the adoption step.
Unless:
- The file is beneath docs/dist/ (generated output, never scanned).
- The markdown is outside docs/ (e.g. README.md, CONTRIBUTING.md, repository-root corpus); it is migrated by the adoption step, not rejected here.
Why: A mixed corpus cannot carry the relationship graph: doc-id and :implements:/:supersedes: edges are AsciiDoc attributes and markdown has nowhere to put them, so format uniformity is the precondition for every other docs rule.
