Title: Name every plan-declared produce/consume artifact in the Bun code that moves it through Cargo
Given: A wagon document under plan/** declares its data contract — produce[]: artifacts the wagon owns; consume[]: artifacts it takes from other wagons — and Bun code moves Cargo for that wagon
When: the wagon's Cargo-moving code or its declared contract is written or changed
Then: Name every declared produce[].name and consume[].name artifact in the Bun module(s) where that wagon moves Cargo, so declaration and carried data cannot drift apart.
Prefer:
- Plan-matching name constants used at the Cargo call sites: `export const CONSUMES = "orders:priced-basket"; // plan: consume[].name` / `export const PRODUCES = "orders:confirmed-order"; // plan: produce[].name`; in `runWagon(step, cargo)`: `const basket = cargo.get(CONSUMES); cargo.put(PRODUCES, { confirmed: true, basket });`.
- If the wagon no longer owns an artifact, correct the plan instead.
- Name your modules as you like; no particular filename is required — what matters is that the module moving the wagon's Cargo names its artifacts.
Avoid:
- Plan produce/consume lists diverging from what is actually put/got through Cargo.
- Putting a wagon's declared names only in a shared or unrelated module that does not move that wagon's Cargo.
- Trying to suppress a finding: it is not suppressible.
Unless:
- The consumer declares no wagon contract (NOT_APPLICABLE).
- The wagon has no implementation anywhere: an unimplemented feature, not a broken contract; another rule governs it.
Why: Core wagon.schema.json only checks the contract is well formed; only a detector reading Bun source and its Cargo idiom can see whether the code carries the declared artifacts.
