Title: Declare abstract Gherkin narrative in every acceptance given/when/then section
Given: An acceptance document with given/when/then sections exists or is being written.
When: You author, edit or review that acceptance.
Then: Every section must carry all three REQUIRED abstract fields: given.abstract (non-empty list of strings, each item a single precondition/setup state), when.abstract (string ≥5 chars, present tense, clear actor and action), then.abstract (non-empty list of strings, each item a single observable outcome).
Prefer:
- Keep abstract fields alongside the structured fields in the same section: abstract for stakeholders (Gherkin), structured for machines (test generation).
- Use identity.purpose as the scenario name; a separate top-level name is not needed.
Avoid:
- Omitting any abstract field or leaving given/then lists empty.
- Bundling several preconditions or outcomes into one item.
- Replacing structured machine fields with the narrative (they coexist).
- Placeholder text that passes length/count checks without describing a real state, action or outcome.
Why: Abstract Gherkin narrative makes each acceptance readable by stakeholders while structured fields stay machine-consumable for test generation.
