Title: Assert SMOKE cases on operator-observable output that proves the acceptance outcome
Given: A test file whose declared Phase is SMOKE contains a case that makes assertions
When: the case's assertions are written or changed
Then: At least one assertion must check, on an operator-observable channel (HTTP response status/body, rendered markup, stdout/stderr, exit code, persisted state, or other operator-observable channel), the externally visible outcome the case claims — the bound acceptance's Then where one is bound — specifically enough that the case turns red if that behavior disappears.
Prefer:
- Read the acceptance's Then first; identify the externally visible consequence that discharges it.
- Exercise the real path and assert on the real HTTP response and its markup (what htmx shows the user), stdout/stderr, exit code, persisted state, or other observable channel: `const res = await fetch("/orders"); expect(res.status).toBe(200); expect(await res.text()).toContain("order-1");` — status is transport evidence; the body check is the acceptance-specific witness.
Avoid:
- Asserting only on objects the test built: `const order = buildOrder({ sku: "x" }); expect(order.sku).toBe("x");` — internal, not SMOKE evidence; it proves the constructor (a unit test's job).
- Treating any observable assertion (e.g. a generic `200`) as sufficient when it does not prove the declared outcome.
- Checking internal calls or mocks instead of the resulting system behavior.
Unless:
- The case makes no assertions at all — skipped here; other rules own that.
Why: The SMOKE label tells the gate real behaviour was exercised, so it must prove something an operator could witness; a self-built object or bare `200` leaves the acceptance (e.g. the new order being visible) unproven.
