Title: Bind every telemetry test to the item and the acceptance that requires it
Given: A test file contains a real `Telemetry:` header (a telemetry test) in a repository that has adopted the telemetry rule family
When: the test is validated or its headers are written or changed, including unchanged tests re-judged after tracking-plan changes
Then: Each `Telemetry:` header must be a well-formed concrete URN resolving to a tracking-plan item, and the test must carry `Acceptance:` bindings to declared acceptances, at least one of whose telemetry decisions requires that item.
Prefer:
- Bind both ends of the proof: `// URN: test:commons:ingress:E001-UNIT-001` / `// Acceptance: acc:commons:E001-UNIT-001` / `// Telemetry: telemetry:event:be:commons:response-invocation-accepted`.
- In a spec covering many acceptances, ensure at least one bound acceptance's decision lists the item.
Avoid:
- Binding an item with no acceptance — it proves something nobody required.
- Binding an acceptance whose decision does not list the item — a test proves a requirement, not an acquaintance.
- Non-concrete or unresolvable Telemetry URNs; Acceptance bindings absent from the plan.
Unless:
- Telemetry test only by URN segment or colocation (no `Telemetry:` header): judged by the captured-sink and identity rules instead.
- Repository has not adopted this rule family (inert until adoption, like every rule in it).
Why: This is the @covers edge of the telemetry graph (acceptance → item → test); without both bindings a test proves nothing required or a relationship the plan never declared.
