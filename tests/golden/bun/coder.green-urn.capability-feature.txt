Title: URN wagon and feature segments are the plan's exact kebab-case identifiers
Given: A Bun source file carries a well-formed six-segment URN header (new or existing)
When: the file is written, edited or checked
Then: The `{wagon}` and `{feature}` segments MUST be the plan's exact identifiers and match `^[a-z][a-z0-9-]*$`.
Prefer:
- During GREEN: derive both values from the feature currently being implemented.
- During GREEN: if the identity is already correct, normalize only casing or separators.
Avoid:
- Touching the name, side or layer segments while fixing wagon/feature.
- Inventing or renaming plan wagons/features to satisfy the header.
- Copying identifiers from a neighboring feature without checking ownership.
Unless:
- URNs that are not six well-formed segments (owned by green-urn-pattern).
- Name, side and layer segments (own rules).
Why: Wagon and feature are case- and separator-sensitive join keys into `plan/`: `Orders` and `orders` differ to a string match, so a wrong header binds to nothing while reading correctly to a human (silent join failure). Kebab-case is the plan's own grammar.
