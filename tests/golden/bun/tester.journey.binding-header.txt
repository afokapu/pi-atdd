Title: Bind each journey spec to exactly one train or journey
Given: A journey spec: a `*.e2e.ts` Playwright file, or any test file whose header comments carry `// Train:`, `// Journey:`, `// URN: test:train:…` or `// URN: test:journey:…`
When: the spec is present in the scanned tree (new or existing, whether or not its header was touched)
Then: Its header block carries exactly one binding header — `// Train: train:<subject>:<slug>` or `// Journey: journey:<id>` — whose id matches the planner's identity grammar.
Prefer:
- Add the binding to the header block, e.g. `// Train: train:orders:place-order` (or `// Journey: journey:buy`).
Avoid:
- A journey spec with no binding header.
- Two binding headers in one spec.
- An id the planner would reject.
- Renaming a spec away from *.e2e.ts to escape the check — header markers still bring it in scope.
Unless:
- Vendored and generated trees (`node_modules`, `dist`, `build`, `_generated`) are never scanned.
- Unit and acceptance tests carrying none of the journey markers are out of scope.
Why: The binding is how a browser test is traced to the plan it exercises; a spec with no binding, two bindings, or an id the planner would reject cannot be traced.
