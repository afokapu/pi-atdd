Title: Declare only a JS/TS-family runtime in a test's Runtime header
Given: A test file collected and executed by the bun suite
When: its header declares the optional `// Runtime:` field (any existing or new declaration, regardless of what was edited)
Then: The declared runtime MUST be in the JS/TS family: bun, browser, isomorphic, typescript, ts, node, js, javascript, deno, vite, astro, or preact.
Prefer:
- Declare the runtime the suite actually executes under, e.g. `// Runtime: bun`.
- Or drop the `// Runtime:` field entirely; the suite's runner is already known from the provider.
- If the test genuinely belongs to a non-JS runtime, move it to the suite of that runtime instead of relabelling it.
Avoid:
- Declaring a non-JS runtime such as `python` on a test that `bun test` collects — it is mislabelled or filed in the wrong suite.
- Restricting test headers to the source-side `bun|browser|isomorphic` vocabulary; the test vocabulary is deliberately the wider JS/TS family.
Unless:
- The test has no `Runtime:` field — the field is optional for tests and absence is not flagged.
Why: Every test file in this stack is collected and executed by `bun test`, a JS/TS runtime, whatever its header claims; a non-JS declaration makes the gate attribute the test to a runner that never executed it.
