Title: Keep every train-level acceptance well-formed
Given: A train file under plan/_trains/ (flat or subject-nested) declares the optional acceptances[] block (WMBT acceptance shape); each entry contributes a derived repo rule via the rule-binding walker.
When: The planner authors, edits or keeps a train-level acceptance that is checked at CONFIRM.
Then: Every train-level acceptance must be well-formed per the train-acceptance constraints (see prefer[0]).
Prefer:
- Satisfy all four constraints: identity.urn matches the acc grammar (acc:<train-id>:<slug>); identity.purpose populated (becomes the rule description); identity.phase in RED|GREEN|SMOKE|REFACTOR; measurable via harness.type OR signal.metric+signal.threshold.
- Copy the exemplar: identity {urn: acc:train:self-compliance:validate-lifecycle:idempotent-on-retry, id: AC-SMOKE-001, purpose: 'Re-running the train with the same idempotency key produces no duplicate side effects', phase: SMOKE}, harness {type: e2e}, signal {metric: duplicate_side_effects_on_retry, threshold: 0}.
- Let the rule id derive: acc:<train-id>:<slug> -> repo.<train-id>.acc-<slug>.
Avoid:
- id: at acceptance-block top level (rule id derives, §3.3).
- disposition: anywhere in repo YAML (walker sets strict, §4.4).
- Retired URN schemes or examples failing the acc grammar/train schema.
- signal.metric without signal.threshold (or vice versa) as sole measurability.
Why: Each acceptance becomes a derived repo rule the walker sets to strict; a bad URN, missing purpose/phase or unmeasurable block yields an unbindable or meaningless rule, so a confirm-blocking validator checks well-formedness.
