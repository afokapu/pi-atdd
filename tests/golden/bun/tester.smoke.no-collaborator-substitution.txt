Title: Preserve the real proof boundary in SMOKE tests
Given: A test file whose declared Phase is SMOKE
When: the tester writes or edits a case in that file
Then: Preserve the real proof boundary: the case MUST exercise the production collaborator through the assembled path the SMOKE acceptance requires, on the real infrastructure or environment the declared smoke proof verifies, and MUST NOT substitute any production collaborator (mock.module, spyOn, jest.mock/spyOn, vi.mock/spyOn).
Prefer:
- Arrange only the minimum preconditions needed for the declared stimulus.
- Observe the acceptance-specific external result after the real collaborator runs.
- If substitution is the intended proof technique, move the case into a UNIT-phase test where it is honest and expected.
Avoid:
- Replacing the collaborator the SMOKE claim depends on because it is expensive, inconvenient or hard to arrange — that changes the question, not the cost.
- Moving the test inward to a unit seam merely because it is easier to control.
- Relabeling a case as SMOKE after using mocks or spies that bypass production behavior.
Unless:
- The file is not SMOKE-phase: UNIT tests may substitute freely.
Why: In a SMOKE proof the boundary is part of the claim: a substituted SMOKE test (perhaps a fine unit test) earns gate credit for the very path it replaced, letting a green suite coexist with a broken deployment.
