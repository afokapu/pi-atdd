Title: Wire a real no-emit typecheck into a TypeScript Bun project's check path
Given: A consumer Bun project with a package.json and at least one .ts/.tsx source
When: the project is worked on or validated (standing obligation)
Then: The project has TypeScript (or a native preview such as tsgo) as a dependency, a tsconfig.json, and a no-emit typecheck script wired into its check path.
Prefer:
- A script (e.g. `typecheck`) running a recognised no-emit checker such as `tsc --noEmit` or `tsgo --noEmit`, invoked by the developer/CI check scripts.
- During GREEN: reuse the existing typechecker and strict config (which checker is the project's choice); add only the minimal missing dependency, config or script; fix type errors from the current behavior instead of weakening compiler options.
Avoid:
- A typecheck no developer/CI script invokes.
- Relying on Bun: it strips types and bundles no tsc.
- "strict": false, or no strict-family flag (e.g. `strict`, `noImplicitAny`), in a tsconfig extending no base.
- Disabling strict checks or adding blanket ignores.
- Replacing the typechecker without necessity, or migrating unrelated configuration while establishing the check.
Unless:
- No .ts/.tsx sources: out of scope.
- Strictness only: a tsconfig that extends a base is never reported.
- The convention hub is never scanned; its .ts files are fixtures.
Why: Bun strips types and ships no typechecker, so without a wired, actually run typecheck a Bun stack is by default less type-safe than a tsc-based one; shape detectors can't confirm code conforms to its types.
