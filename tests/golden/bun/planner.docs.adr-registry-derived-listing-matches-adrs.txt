Title: The ADR registry lists exactly the declared ADRs, with no missing and no stale entry
Given: A docs corpus with a decisions directory holding zero or more ADR files. decisions/index.adoc may or may not exist yet.
When: The docs corpus is validated or reviewed, or you plan or author any docs change (typically adding, renaming or removing an ADR, editing its :adr-id: or :decides:, or editing decisions/index.adoc)
Then: The registry listing in docs/architecture/decisions/index.adoc names exactly the ADRs the corpus declares. Every ADR file is listed and every listed id has an ADR file.
Prefer:
- Put `// BEGIN GENERATED: adr-register` / `// END GENERATED: adr-register` markers where the list belongs, so that only that region is read.
- Run `atdd-bun docs adr-register --check` to confirm there is no drift. It writes nothing.
Avoid:
- Leaving a stale entry after an ADR is renamed or removed. A list that names something is read as authoritative, so the stale entry survives review.
- Mentioning ADR ids in prose without markers. Outside ---- blocks those mentions count as listed references. Add the markers if prose should be ignored.
Unless:
- Prose around the entries (a title, an introductory paragraph) is not compared. Only the set of ADR references is.
- A decisions directory with no ADRs needs no entries. An empty registry is correct.
Why: The check is bidirectional on purpose. A missing entry is the obvious drift. A stale entry (an ADR listed after its file was renamed or removed) is the one that survives review, because a list that names something is read as authoritative about it.
