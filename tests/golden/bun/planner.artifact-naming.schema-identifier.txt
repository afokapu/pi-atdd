Title: Use the bare artifact name as a contract schema's $id
Given: You are planning, authoring or editing a contract schema, or a wagon produce/consume entry that references one.
When: The schema's $id is set, changed or present, or a reference to the contract is written.
Then: Set the contract schema's $id to the clean artifact name {theme}:{resource}[.{category}] — no 'urn:contract:' prefix and no version suffix.
Prefer:
- Required: record the contract's version in a separate top-level version field, never inside $id.
- Write the wagon produce/consume reference as contract:{artifact_name}, using the same artifact name as the $id.
- Keep $id stable across versions; express a new version through the separate version field.
Avoid:
- Adding a version suffix to $id (e.g. ...:v1); it breaks identity stability across versions.
- Prefixing $id with 'urn:contract:'.
Why: Keeping the version out of $id means the artifact keeps the same identity across versions, so $id and the contract: reference always point to one stable artifact.
