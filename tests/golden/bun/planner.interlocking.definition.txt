Title: Model a diverging journey as an interlocking: a declared artifact-keyed registry selecting the next linear train
Given: A planned journey diverges: which train runs next depends on an artifact produced earlier.
When: The planner decomposes the journey into trains and records how the branch is routed.
Then: Declare the branch as an interlocking: a domain-owned, schema-valid routing registry (artifact_urn -> train_id) keyed by the produced artifact (the divergence signal), composing strictly-linear trains into a branching journey-of-journeys.
Prefer:
- Key dispatch by one produced artifact URN; a composite (urn, discriminant) key is exceptional (planner.train.dispatch-map-is-registry, planner.train.dispatch-composite-key-exceptional).
- Keep trains linear; branch between trains, in the interlocking (planner.train.linearity).
- Name only the routing decision; leave the route-control runner and dispatcher to coder/tester.
Avoid:
- Branching inside a train.
- Expressing the dispatch map as code or an imperative map.
- Specifying runner/dispatcher mechanics in planner artifacts.
- Treating this definition as an enforced check; enforcement lives in the constraint/rule nodes that require it.
Why: An interlocking gives a diverging journey a stable meaning: the routing decision is a declared, artifact-keyed registry rather than branching inside trains, so trains stay linear.
