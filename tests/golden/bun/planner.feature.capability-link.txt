Title: Register each feature in exactly one wagon manifest
Given: A feature exists in the plan, and wagon manifests (each wagon's _features.yaml listing its features) record which wagon owns which feature.
When: You create, change (including acceptance/WMBT-only edits), move, remove or assess any feature, or edit a wagon manifest. A feature already listed in exactly one manifest is compliant and needs no registration change.
Then: Register each feature under exactly one wagon's _features.yaml manifest.
Prefer:
- Add the feature's entry to its owning wagon's _features.yaml in the same change that creates the feature, following the entry format already used in that manifest.
- When moving a feature between wagons, remove the entry from the old wagon's manifest and add it to the new one in the same change.
- Where the repository places features under their wagon's directory, list the feature in that wagon's manifest so ownership and location agree.
Avoid:
- Orphan features that no wagon manifest lists.
- Listing the same feature in two or more wagons' _features.yaml manifests.
- Leaving stale manifest entries that point to removed or renamed features.
Why: A feature belongs to exactly one wagon; the wagon manifest is the link that makes that ownership explicit and traceable.
