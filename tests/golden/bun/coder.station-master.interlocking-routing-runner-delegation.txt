Title: Interlocking routes go through InterlockingRunner, and every route ends in TrainRunner (Bun)
Given: The Bun Station Master (server.ts) has a JOURNEY_MAP with at least one {interlockingId, path} route object
When: you write or change server.ts
Then: server.ts MUST resolve each interlocking route through InterlockingRunner, and TrainRunner MUST perform the final train execution for every route: both the train InterlockingRunner selects and each direct trainId.
Prefer:
- Core call model: Station Master -> InterlockingRunner.resolveTrain(action, inputs, state) -> TrainRunner.execute(selectedTrainId, ...)
- Bun branch from the fix hint: new InterlockingRunner(path).execute(...) -> TrainRunner.execute(...). Use the runner API that actually exists
- import { InterlockingRunner } from "./trains/interlocking"; import { TrainRunner } from "./trains/runner";
Avoid:
- Declaring an interlocking route without referencing InterlockingRunner (finding: unlinked)
- Never reaching TrainRunner for the selected train (finding: no delegation)
- Executing direct trainId routes through any executor other than TrainRunner
Unless:
- JOURNEY_MAP declares no interlocking route object: a pure direct-train Station Master carries no interlocking obligation
Why: In both cases, direct and interlocking, TrainRunner performs the final train execution. A Station Master that declares an interlocking route but never routes through InterlockingRunner, or never reaches TrainRunner, breaks the contract.
