Title: Make the runtime load and resolve from the declared route space, not transcribe it
Given: A consumer declares guarded interlocking routes (interlocking YAML, train definitions)
When: Its runtime under the runtime selector is written, changed or assessed — including when no runtime exists yet
Then: The consumer MUST have a runtime that reads the declaration it is given: an InterlockingRunner built with an interlocking YAML path loads that path and resolves from what it read; a TrainRunner takes wagon order from the train definition.
Prefer:
- Load the declaration (e.g. yaml.safe_load of the path's text) and resolve from the loaded data; loading may live in a sibling loader module.
- Resolve through a route_by_id-style accessor over the loaded route space, not an inline filter (provenance scan reports inline filters as undecidable).
Avoid:
- Transcription: storing the path and returning hardcoded resolution fields or a literal train_id -> wagons map that match the declaration today.
- Treating passing text-level rules as proof the plan is executed.
Unless:
- The consumer declares no interlocking route space.
- A runtime that loads the declaration is never checked for route literals.
Why: A transcribing runtime matches the plan when written, then diverges silently as the plan is edited while every literal check still passes; an absent runtime at least fails loudly. Reading the declaration makes the train YAML the runtime's source of truth.
