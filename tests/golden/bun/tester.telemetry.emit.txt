Title: Telemetry tests assert on emission
Given: A Bun test identified as a telemetry test by a -TELEMETRY-, -EVENT- or -METRIC- URN kind segment, or by *.telemetry.test.* filename colocation
When: the test exists in the suite (every telemetry-identified test, new, changed or unchanged, is scanned)
Then: The test MUST contain an emission assertion: toHaveBeenCalled / toHaveBeenCalledWith / toHaveBeenCalledTimes on the emitter, or an expectation on .emit / .emitted / .capture / .track / .record.
Prefer:
- Inject a spy or captured emitter and assert the emission, e.g.: const emit = mock(() => {}); placeOrder({ sku: "x" }, { emit }); expect(emit).toHaveBeenCalledWith("order_placed", { sku: "x" });
Avoid:
- Asserting only the return value in a telemetry test: it proves the function ran, not that the event fired.
Unless:
- Only telemetry-identified tests are in scope; tests without a TELEMETRY/EVENT/METRIC URN segment or *.telemetry.test.* filename are not scanned.
Why: The event is the entire point of a telemetry test: dashboards, alerts and downstream analytics are built on the emission, not on the return value.
