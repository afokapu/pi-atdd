Title: Run axe in every A11Y spec and assert on its violations
Given: A spec is identified as accessibility: it has an `A11Y` test URN, or its file name contains an `a11y` token
When: The tester writes or changes that spec
Then: The spec must run the axe harness and assert on the returned `violations` in a way that can fail. This requires importing `AxeBuilder` from `@axe-core/playwright` (under any local name) and calling `new AxeBuilder(...).analyze()`.
Prefer:
- Assert that there are no violations: `toEqual([])`, `toHaveLength(0)`, or `toBe(0)` on the count
- Or use a bounded assertion: `toBeLessThanOrEqual(n)` or `toBeLessThan(n)`
- `const results = await new AxeBuilder({ page }).analyze(); expect(results.violations).toEqual([]);`
Avoid:
- An accessibility spec that navigates the page but never runs axe
- Running axe and then never asserting on the result
- Tautological assertions that cannot fail, such as `toBeGreaterThanOrEqual(0)`. These do not count as assertions
Why: An accessibility spec that navigates but never runs axe, or never asserts on the result, passes no matter what state the page is actually in.
