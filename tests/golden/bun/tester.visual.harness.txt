Title: Make every VIS spec compare a screenshot
Given: A browser spec — a `*.e2e.ts` file run by Playwright, or any test file whose header comments carry a journey marker (`// Train:`, `// Journey:`, `// URN: test:train:…`, `// URN: test:journey:…`), even if misnamed; NOT a unit test that merely mentions a journey URN in a string — identified as visual: it carries a `VIS` test URN, or its file basename contains a `visual`/`vis` token (a whole name segment, not an arbitrary substring).
When: The spec is evaluated (new, changed, or existing unchanged).
Then: The spec MUST call `toHaveScreenshot()` or `toMatchSnapshot()`.
Prefer:
- Assert the rendered state with a named screenshot, e.g. `await expect(page).toHaveScreenshot("checkout.png");`.
Avoid:
- Labelling a spec VIS (URN or file name) while only asserting DOM/text, so it captures nothing and performs no visual regression.
- Renaming the file or dropping the VIS URN merely to escape this check instead of adding the screenshot comparison.
Unless:
- The file lives in a vendored or generated tree (`node_modules`, `dist`, `build`, `_generated`); these are never scanned.
Why: A visual spec that captures nothing performs no visual regression.
