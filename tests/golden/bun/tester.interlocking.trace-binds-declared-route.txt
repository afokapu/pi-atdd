Title: Bind interlocking trace assertions to the declared route (Bun)
Given: A Bun e2e test (e2e/**/*.ts) in an interlocking context
When: it references or inspects the bare `trace` identifier (runtime trace on an interlocking execution's TrainResult), with or without assertions
Then: Assert every required trace field — interlockingId, routeId, selectedTrainId, routeCategory, guardId, resolutionStrategy, resolutionReason — binding the executed route to its interlocking YAML declaration and resolution outcome.
Prefer:
- Extend the flagged trace assertion so the captured trace is checked for all seven fields (TS camelCase).
- Assert values against the interlocking YAML declaration the run came from.
Avoid:
- Checking only one field (e.g. selectedTrainId): a different route/category/guard would still match.
- Naming fields only in comments; comments are masked.
Unless:
- The test does not reference the runtime `trace` object.
- The test is non-interlocking (no interlocking route/train/interlocking token or runner symbol).
- The stack is not Bun (owned by its own workspace package).
Why: The TrainResult trace proves which declared route actually executed; a trace test that does not bind the declared route lets execution drift from declaration silently and undetected.
