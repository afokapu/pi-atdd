Title: Keep wagon manifests and feature files cross-referenced both ways
Given: The plan contains feature YAML files and/or wagon manifests with features[] entries.
When: The planner authors, edits, moves, deletes or reviews any of them.
Then: Every feature file is referenced by its wagon manifest's features[], and every features[] entry resolves to an existing feature YAML file.
Prefer:
- Update features[] in the same change that adds, renames or removes a feature file.
- Record an intentionally wagon-less feature in the features_orphaned allow-list instead of leaving it silently unreferenced.
Avoid:
- A feature file no wagon manifest lists (feature -> wagon gap).
- A features[] entry pointing to a missing, renamed or deleted feature file (wagon -> feature gap).
- Allow-listing features that belong to a wagon just to silence the validator.
Unless:
- The feature is on the features_orphaned allow-list (exempts only feature -> wagon; features[] entries must still resolve).
Why: Coverage means each feature is referenced by its wagon and vice versa; a one-sided link leaves untracked features or dangling references, breaking plan traceability.
