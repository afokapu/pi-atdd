Title: Write every URN marker with all six segments in canonical order
Given: A file in scope carries a `URN:` marker (new, edited or pre-existing)
When: the marker is written, edited, or checked
Then: The marker reads exactly `component:{wagon}:{feature}:{Name}:{side}:{layer}` — the literal `component` first, then exactly five non-empty segments.
Prefer:
- During GREEN, derive each segment from the plan, filename, execution side, and architectural responsibility.
- During GREEN, fix only the malformed or missing segment; keep already-correct identity segments unchanged.
Avoid:
- When fixing URN grammar (do not broaden): inventing placeholder segments.
- When fixing URN grammar (do not broaden): renaming implementation artifacts solely to make a guessed URN fit.
- When fixing URN grammar (do not broaden): altering plan ownership.
Unless:
- No `URN:` marker: skipped here; owned by `green-urn-marker`.
- Segment CONTENT is validated by the wagon-feature, name, side and layer rules; this rule checks shape only.
Why: Each segment is a join key against plan/: wagon and feature locate the work item, name the component, side and layer its architectural place. A URN missing a segment resolves to nothing — as unbound as no marker, while LOOKING traceable in review.
