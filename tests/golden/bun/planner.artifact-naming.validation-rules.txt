Title: Validate artifact names against format, semantic and technical rules
Given: A plan, wagon, acceptance, contract or consumer declares, references, uses or validates an artifact name
When: that name, a reference to it, or its contract file/$id is added, used or changed
Then: The artifact name must pass all three validation rule categories — format, semantic and technical.
Prefer:
- Format: theme lowercase with no separators; category/aspect/variant kebab-case; ':' for descent (hierarchy levels); '.' for variants.
- Semantic: theme from the approved taxonomy; each hierarchy level adds value; aspect a concrete noun; variant a state/type/facet.
- Technical: a contract file exists at contracts/{segments}.schema.json, where {segments} is derived by splitting the name on ':' and '.'; its $id is urn:contract:{artifact_name}.
- The URN matches the name exactly, and all consumers reference that same name.
Avoid:
- Deep variant nesting.
- A URN that differs in any way from the name.
- Consumers referencing a different spelling or alias of the name.
- Hierarchy levels that add no value.
Why: The name is the join key between plans, contracts and consumers; deriving format, meaning and file path from one name lets contracts be located mechanically and catches drift.
