Title: REFACTOR only after GREEN, guided by the metrics sensors
Given: a governed ATDD Bun task whose current behavioral acceptance has passed for the first time (behavioral GREEN)
When: you change code to improve its design, including in response to a metrics sensor finding
Then: Start REFACTOR only after behavioral GREEN. Keep the now-green behavior fixed, and address refactor-sensor findings one at a time by following each finding's Diagnose / Prefer / Avoid / Verify guidance.
Prefer:
- The refactor sensors are the bun_ts_metrics_detector rules: coder.bun.complexity-cyclomatic, coder.bun.complexity-length, coder.bun.complexity-nesting, coder.bun.dead-code-reachability, coder.bun.duplication-intra-layer, coder.bun.quality-comments, coder.bun.quality-mi.
- Address one finding at a time, using that finding's smell-specific Diagnose / Prefer / Avoid / Verify guidance.
- Treat each finding as evidence of a design smell, not as the design objective. Fix the smell, not the number.
- These sensors may run at any time and stay strict. The phase changes your response, not the validator.
Avoid:
- Starting REFACTOR before the acceptance has passed for the first time.
- Adding behavior during REFACTOR.
- Metric gaming and unrelated redesign.
- Forcing a sensor violation just to keep a ceremonial phase boundary.
Unless:
- If a refactor sensor is already satisfied by the smallest correct implementation, keep that result.
Why: GREEN and REFACTOR are different search problems, and splitting them does not change enforcement. REFACTOR uses the seven metrics findings as guided design sensors while preserving the behavior GREEN established.
