Title: Give each acceptance a legacy id of the form AC-{STEP}-{NNN}
Given: You are authoring or editing an acceptance and setting its identity.id (the legacy id, kept for backward compatibility).
When: You write the identity.id value.
Then: Write identity.id as AC-{STEP}-{NNN}, where {STEP} is the step code mapped from the step name (define→DEF, locate→LOC, prepare→PREP, confirm→CONF, execute→EXEC, monitor→MON, modify→MOD, resolve→RES, conclude→CONC) and {NNN} is the number, e.g. AC-EXEC-201, AC-CONF-004.
Prefer:
- Derive {STEP} strictly from the step_code mapping (step-name → id code) rather than abbreviating the step name ad hoc.
- Keep {NNN} as a three-digit number as in the canonical examples (AC-EXEC-201, AC-CONF-004).
Avoid:
- Using full step names or non-mapped abbreviations in the id (e.g. AC-EXECUTE-…, AC-CFG-…).
- Treating the legacy AC id as a replacement for the acceptance URN; it is a parallel, backward-compatibility identifier.
Why: The legacy AC id is kept in identity.id for backward compatibility.
