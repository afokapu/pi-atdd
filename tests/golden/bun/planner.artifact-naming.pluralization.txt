Title: Use singular aspects for item schemas and correctly pluralized aspects for collections
Given: An artifact name's aspect refers to a schema that is either a single item or a collection (e.g. in a plan, wagon, WMBT, acceptance, doc or the schema itself)
When: the planner writes, renames or checks that aspect, or the schema's item/collection shape changes
Then: Use the singular aspect for an item schema and the plural aspect for a collection schema, following English pluralization rules.
Prefer:
- Regular: add 's' (fragment->fragments, color->colors).
- Irregular: English irregular form (analysis->analyses, policy->policies, datum->data, index->indices, child->children).
- Uncountable: explicit suffix (config vs config.collection; data.item vs data.items).
- Compound: pluralize the primary noun (button-group->button-groups, session-state->session-states).
Avoid:
- Plural aspect on an item schema, or singular aspect on a collection schema.
- Naive 's' plurals of irregular nouns (analysiss, policys, childs).
- An uncountable collection aspect without an explicit suffix (e.g. bare config or data for a collection); a bare item like config is fine.
- Pluralizing a non-primary noun of a compound name.
Why: Cardinality is read from the aspect's singular/plural form, so correct plurals keep the item-vs-collection signal reliable.
