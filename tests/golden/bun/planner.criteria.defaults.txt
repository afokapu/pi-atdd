Title: Seed acceptance given blocks with the canonical defaults
Given: An acceptance criterion's given section is being authored or edited.
When: You fill in the given block (auth, builders, time, stubbing, knobs).
Then: Start the given section from the canonical defaults: auth scopes [], builders [], time {}, stubbing policy strict with overrides [], knobs {}.
Prefer:
- Add non-default values only where the acceptance's behaviour actually needs them.
- Express any needed stub as an explicit entry in stubbing.overrides on top of the strict default.
- When a harness template applies, let its given specialize these defaults instead of replacing them.
Avoid:
- Granting auth scopes, adding builders, freezing time or setting knobs that the acceptance's behaviour does not require.
- Relaxing the default strict stubbing policy merely to make an acceptance easier to satisfy.
Why: A shared, minimal default given makes every criterion start from the same strict, permission-free baseline, so any extra setup is a deliberate, reviewable deviation.
