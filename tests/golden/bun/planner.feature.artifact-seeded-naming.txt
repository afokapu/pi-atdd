Title: Seed feature names from the wagon's produce/consume artifact as {verb}-{object}
Given: A planner is authoring or renaming a feature in a wagon that has produce/consume artifacts
When: Choosing the feature's name
Then: Derive the name from a produce/consume artifact (the feature seed) as kebab-case {verb}-{object}, where the verb comes from the artifact type's verb list and the object from the artifact's domain or resource.
Prefer:
- Step 1: identify the seed artifact from the wagon's produce/consume entries
- Step 2: classify the artifact type as event, state, data or config
- Step 3: select the verb from that type's verb list (the lists are defined by convention planner.feature.verb-selection-by-artifact-type)
- Step 4: choose the object from the artifact's domain OR its resource (either is allowed; see examples)
- Step 5: combine as {verb}-{object} in kebab-case
- Data example (object from resource): mechanic:decision.choice (data) -> make-choice
- State example (object from resource): mechanic:timebank.remaining (state) -> track-timebank
- Event example (object from domain): match:started (event) -> start-match
Avoid:
- Inventing feature names not traceable to any produce/consume artifact
- Using a verb outside the list for the artifact's type
- Names not in {verb}-{object} kebab-case form
Why: Seeding names from produce/consume artifacts keeps features traceable to the wagon's contract and gives consistent, predictable verb-object names (also used as the feature URN segment).
