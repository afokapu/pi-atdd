Title: Return a structured InterlockingResolution from resolveTrain, not a bare trainId
Given: A Bun/TS InterlockingRunner exposes a resolveTrain(...) method
When: resolveTrain resolves a route
Then: resolveTrain resolves a structured InterlockingResolution model defining interlockingId, routeId, trainId, trainPath, category, guardId, resolutionStrategy, and reason — not a bare trainId string.
Prefer:
- `export interface InterlockingResolution { interlockingId: string; routeId: string; trainId: string; trainPath: string; category: string; guardId: string; resolutionStrategy: string; reason: string; }`
- Define the model and return it from resolveTrain: `return { interlockingId, routeId, trainId, trainPath, category, guardId, resolutionStrategy, reason, };`
Avoid:
- Resolving only a bare trainId string from resolveTrain.
- Judging category agreement from a digit parsed out of the identity validation instead of the target train's `category` field.
Unless:
- No InterlockingRunner with a resolveTrain method is present (separate coder.bun.interlocking-runner-exists concern).
Why: A bare trainId loses the routeId, guardId, category, resolutionStrategy, trainPath and the human-readable reason needed for trace and projection equivalence.
