Title: Assert the exact telemetry URN in telemetry tests
Given: A Bun test is a telemetry test: it claims URNs in `// Telemetry:` headers, or is identified by URN segment or colocation.
When: Writing, changing or checking that test, including edits to its header or to a claimed item's identity.
Then: Every URN claimed in the test's `// Telemetry:` header appears verbatim in the test's code as an assertion string (a string literal that takes part in an assertion, not an unused literal); a headerless telemetry test asserts at least one concrete telemetry: URN. Once generated contracts ship, the item's contract identifier satisfies this the same way.
Prefer:
- Name the item in the assertion itself: expect(emit).toHaveBeenCalledWith("telemetry:event:be:example:item-accepted", { item_id: "i-1" });
Avoid:
- Asserting the mocked emitter was called with anything.
- Asserting a URN prefix or a captured-anything matcher.
- Relying on the URN in the header or any comment — comments do not assert.
- A quoted URN present in code but never used in an assertion.
Unless:
- The repository has not adopted this rule family — inert until adoption, like every rule in the family.
Why: An any-call assertion proves emission, not that the planned item fired; renames and copy-paste drift hide there. Exact URNs keep assertion and plan from silently diverging.
