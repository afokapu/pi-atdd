Title: Take spacing, radii, and durations from foundations tokens in UI files
Given: The repository has a design root (`design`, `design_system`, or `design-system` dir; its first subdirectory names the layer) and you edit a UI file anywhere outside its tokens/foundations layer
When: the file declares `margin`, `padding`, `gap`, `inset`, `top`/`right`/`bottom`/`left`, `border-radius`, or `transition`/`animation` (CSS, JSX style objects where a bare number is a length, or inline/`<style>` HTML in .ts/.mts literals)
Then: Take those lengths > 1px and non-zero durations from foundations tokens (`var(--…)`); never hardcode them.
Prefer:
- Use the existing foundations scale for spacing, inset, radius, and duration.
- During GREEN: reuse the nearest existing semantic or scale token.
- During GREEN: add a foundation value only when the design genuinely needs a distinct one.
- During GREEN: change only the style declaration the acceptance needs.
Avoid:
- One-off tokens that merely rename a hardcoded literal.
- Bypassing the scale for speed.
- Normalizing unrelated styling.
Unless:
- Value is 0 or 1px (hairlines are not design decisions).
- Custom property definition (`--space-3: 12px`), wherever it lives.
- File is in the tokens/foundations layer.
- Width, height, or font size.
- Test file (`*.test.*`, `*.spec.*`) or vendored/build directory.
- No design root in the repository: no system to connect to yet.
Why: Spacing and motion are an interface's rhythm; each hardcoded `13px` is a new step on a scale nobody chose, eroding it one component at a time.
