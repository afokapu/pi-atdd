Title: Route every train a browser spec covers from an interlocking
Given: A browser spec exists in the repository: a *.e2e.ts file run by Playwright, or any test file (any name) whose header comments carry a journey marker (// Train:, // Journey:, // URN: test:train:…, // URN: test:journey:…)
When: the spec binds to a declared train
Then: That declared train MUST be selected by at least one interlocking route.
Prefer:
- Route the train from an interlocking so the application can actually reach it.
- Or rebind the spec to a train that an interlocking route already selects.
Avoid:
- Keeping a spec green against a train nothing in the application can reach.
- Renaming a browser spec away from *.e2e.ts to dodge the check; header journey markers still classify it.
Unless:
- The spec is in a vendored or generated tree (node_modules, dist, build, _generated) — never scanned.
- The bound train is undeclared — that is reported by tester.htmx.e2e-binds-declared-subject, not here.
Why: A spec can stay green while exercising a train nothing in the application can reach; covering an unrouted train proves nothing about the product.
