Title: Declare a test URN header in every test file
Given: Any `*.test.*`/`*.spec.*` file (new or existing) outside vendored/build dirs
When: it is in the test-file scan scope
Then: Its leading comment block, above the first real code line (imports included), carries `// URN: test:{wagon}:{feature}:{ACCEPTANCE-ID}`.
Prefer:
- Add the header above the imports:
// URN: test:orders:checkout:E001-SMOKE-001-renders-row
// Acceptance: acc:orders:E001-SMOKE-001-renders-row
// Phase: SMOKE
// Layer: integration
- Bind via the header, keeping the file layout; multi-acceptance files need no rename.
Avoid:
- A URN below imports or code — it reads as missing.
- A `URN:` value without the `test:` scheme.
- Encoding acceptance ids in filenames instead of the header; filenames are never parsed.
Unless:
- Not a test file (source files are the coder extension's business).
- In a vendored or build directory (never scanned).
Why: The URN is the coverage gate's foundation: without it the gate cannot attribute the test or report coverage, and marks the acceptance uncovered while the test passes. Header, not filename, because wagon-level files cover several acceptances; a filename rule would force renaming the suite.
