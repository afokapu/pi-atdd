Title: Cover every presentation component with a SMOKE browser spec named after its wagon
Given: A `.tsx`/`.jsx` component under a `presentation/` path segment (wagon = the segment before `presentation`).
When: The component is added or changed, or the detector finds it uncovered.
Then: Ensure this component is covered by a SMOKE browser spec whose path names the component's wagon.
Prefer:
- Add a SMOKE spec whose file name contains the wagon, e.g. `e2e/checkout-cart.smoke.e2e.ts`.
- Make the spec a real browser spec: a `*.e2e.ts` run by Playwright, or a test file whose header comments carry a journey marker.
Avoid:
- Relying on structural/unit tests as coverage — they stay green while the rendered feature is blank.
- Counting a unit test that merely mentions a journey URN in a string as a browser spec.
- Naming a smoke spec without the wagon, so coverage cannot be attributed.
- Treating an existing wagon-named spec as covering every component in the wagon without it actually covering this one.
Unless:
- The component is in a vendored or generated tree (`node_modules`, `dist`, `build`, `_generated`) — never scanned.
- The component is outside a `presentation/` segment — out of scope.
Why: Structural tests stay green while a rendered feature is blank; only rendering it in a browser proves it appears.
