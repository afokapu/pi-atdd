Title: Ship an InterlockingRunner with resolveTrain when JOURNEY_MAP declares interlocking routes (Bun)
Given: A Bun consumer's server.ts JOURNEY_MAP declares at least one {interlockingId, path} interlocking route object
When: the consumer is changed or checked (any file, whenever the route was added)
Then: Define a `class InterlockingRunner` under src/trains/** exposing a `resolveTrain(action, inputs, state)` entry point.
Prefer:
- e.g. src/trains/interlocking.ts: `export class InterlockingRunner { constructor(private readonly interlockingYamlPath: string) {} resolveTrain(action: string, inputs: Record<string, unknown>, state?: unknown): InterlockingResolution { ... } }`.
- resolveTrain evaluates guarded routes, resolves exactly one admissible train, then delegates to TrainRunner.
Avoid:
- Route objects in JOURNEY_MAP with no InterlockingRunner class (no route-control layer at all).
- An InterlockingRunner class without resolveTrain.
- A runner outside src/trains/** or only in generated/vendored trees (never scanned).
Unless:
- Pure direct-train consumer: no route object in JOURNEY_MAP and no InterlockingRunner class.
Why: An interlocking is executable only as a route-control component; resolveTrain evaluates guarded routes and picks one admissible train before delegation, so without it declared routes cannot run.
