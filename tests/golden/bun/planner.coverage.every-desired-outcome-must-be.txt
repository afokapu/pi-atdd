Title: Reference every WMBT from at least one feature
Given: The plan contains one or more WMBT files.
When: You author, change or validate the plan.
Then: Every WMBT file must appear in at least one feature's wmbts list (wmbt -> feature coverage).
Prefer:
- When authoring a WMBT, add it in the same change to the wmbts list of the feature it serves.
- When splitting, renaming or removing a feature, re-home each of its WMBTs into another feature's wmbts list.
Avoid:
- Orphan WMBT files that no feature references, whether new or pre-existing.
- Gaming coverage by dumping unrelated WMBTs into an arbitrary or catch-all feature's wmbts list just to satisfy the check.
Why: A WMBT that no feature references is untraceable to user-facing value and falls outside wagon/feature coverage; wmbt -> feature coverage is the link that lets lower-level coverage (WMBT -> acceptance) roll up to features and wagons.
