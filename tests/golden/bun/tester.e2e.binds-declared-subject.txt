Title: Bind each journey spec to a train or journey declared under plan/
Given: plan/ declares at least one train or journey, and a browser spec exists (a *.e2e.ts file run by Playwright, or a test file with a journey marker header)
When: the spec's binding is checked against plan/
Then: The train or journey the spec binds to MUST be declared under plan/.
Prefer:
- Bind to the declared subject the spec actually exercises: find the plan subject reached by its entrypoint and interactions; use that exact declared id in the header.
- If the intended subject is absent from the plan, return to the authorized planning flow instead of inventing it in the tester repair.
Avoid:
- Choosing any resolvable declared subject merely to clear the finding (false journey coverage).
- Changing the binding to match a convenient test that proves another journey.
- Declaring a new train or journey solely so an existing spec has something to bind.
Unless:
- No plan (no trains, no journeys): out of scope.
- node_modules, dist, build, _generated are never scanned.
- Malformed bindings belong to tester.htmx.journey-binding-header.
Why: The binding traces a browser test to the plan it exercises; no binding, two bindings, or an id the planner would reject is untraceable. Resolution is necessary but not sufficient: the subject must be the one walked, and plan changes only when product behavior requires it.
