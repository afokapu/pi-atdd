Title: Tag every issue-body dependency entry as prereq, merged, sibling, or parallel
Given: An issue body has a Dependencies section containing '#N' references (dependency entries), whether new or already present
When: That issue body is authored, edited, reviewed, or validated
Then: Every #N dependency entry must carry a trailing classification tag that is exactly one of: prereq, merged, sibling, or parallel.
Prefer:
- Put the classification as a trailing marker on each #N entry
- Use prereq for work that must merge before this issue can proceed and merged for a prereq that has already landed. Use sibling or parallel for related work that runs alongside this issue and is not waited on. The source does not distinguish sibling from parallel, so either tag satisfies the rule for such work.
- When an existing issue body has untagged or wrongly tagged entries, fix the tags on those entries
Avoid:
- Leaving any #N entry untagged, or using a tag other than prereq/merged/sibling/parallel
- Dropping or moving real dependencies out of the Dependencies section just to avoid having to classify them
Why: Classifying each dependency prevents the session-template merge-wait loop from hanging on sibling or parallel work.
