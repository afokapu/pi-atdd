Title: Decompose plans by user-facing jobs, not by how the system is built
Given: A planner is decomposing sources into plan items (wagons, WMBTs, acceptances).
When: The planner writes the decomposition.
Then: Each plan item states what the system does — a user-facing job it performs (domain capability) — not how it is built.
Prefer:
- Reframe an implementation-flavored source to the user-facing job it serves: 'use redis for caching' becomes 'browse catalog pages with instant response'.
- Alternatively, route an implementation decision (technology choice) to tests/ADRs instead of the plan.
- Do this reframing before writing the job statement, so the job grammar operates on user-facing jobs.
Avoid:
- Plan items describing how the system is built instead of what it does for the user.
- Keeping implementation-flavored source text as a plan item instead of reframing it to a user-facing job or routing it to tests/ADRs.
Why: The plan decomposes what the system does (user-facing jobs), not how it is built; implementation decisions belong reframed to the job they serve or in tests/ADRs.
