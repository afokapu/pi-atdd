Title: Make each tracking-plan item's identity mirror its path
Given: Telemetry is adopted, and a JSON file exists under the telemetry root. The root is `telemetry/` by default. If topology.telemetry_root is set in atdd-bun.yaml, that path replaces the default. The file may be new, changed or unchanged.
When: You plan, author, rename or review a tracking-plan item at <root>/<theme>/<artifact>/{event|trace|metric|log}.<plane>[.<measure>].json
Then: Make the item's declared identity mirror its path: id = telemetry:{kind}:{plane}:{theme}:{artifact}[:{measure}], logical_artifact = telemetry:{theme}:{artifact}, and the file name's kind, plane and measure equal the declared fields.
Prefer:
- Name the file for what it is, then derive id and logical_artifact from the path.
- Keep the file valid against telemetry-plan.schema.json. Declare id, a SemVer version, logical_artifact, kind, plane, owner, purpose, acceptances, properties and required. Optionally add forbidden_properties. Give each property a type, classification and cardinality. Every `required` name must be declared in `properties`. Metric dimensions are optional, but each one present must declare cardinality.
- Give every metric item a measure segment (metric.<plane>.<measure>.json, id ending :{measure}). Never give an event, trace or log item a measure segment.
Avoid:
- Renaming a file or hand-editing an id so that the path and the identity drift apart
- Declaring the same concrete id in two files
- Putting notes, indexes or generated bundles under the telemetry root
- Treating a logical artifact as an exporter event
Unless:
- Telemetry is not adopted: there is no telemetry root and no acceptance telemetry declaration. Adoption means creating the tree or making the first acceptance decision.
Why: The telemetry tree is a registry, not a suggestion. The path is the authority for identity, so a renamed file or a hand-edited id cannot drift apart silently.
