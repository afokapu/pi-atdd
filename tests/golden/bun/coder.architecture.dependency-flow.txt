Title: Import only from your own or a lower design-system layer
Given: a file inside a named layer of a design root (tokens/foundations 0, primitives 1, components 2, templates 3)
When: any of its imports resolves (relative path or alias naming the design directory) into the design system
Then: each such import MUST target the file's own layer or a lower one; upward edges (tokens→primitives, primitives→components, components→templates) are forbidden
Prefer:
- Keep imports same-layer or downward: tokens -> foundations -> primitives -> components -> templates.
- Reuse an existing lower-layer value or component when possible.
- Move a genuinely shared piece only to the lowest layer that actually owns it.
- Compose upward rather than importing upward.
Avoid:
- Reshuffling unrelated design-system files.
- Creating a new layer or generic abstraction for one dependency.
- Hiding an upward dependency behind a barrel.
Unless:
- Imports within the same layer are allowed.
- Files directly under the design root, outside any named layer, are not layered.
- Test files (*.test.*, *.spec.*) and vendored/build directories are never scanned.
- No design root: not judged; there is no system to connect to yet.
Why: A hierarchy is only a hierarchy if dependencies flow one way; a primitive that imports a component can't be reused without dragging it along, and the layers collapse into one tangle.
