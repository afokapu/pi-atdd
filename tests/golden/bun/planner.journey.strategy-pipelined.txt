Title: Overlap producers and consumers only with an explicit streaming protocol
Given: A journey with producers and consumers; pipelining is meant for streaming/chunked workloads where first-result latency or memory dominates
When: the planner overlaps producers and consumers through incremental artifact delivery
Then: Overlap them only with an explicit streaming protocol that preserves backpressure, ordering, partial failure, stream completion and resource bounds.
Prefer:
- Acceptances that test slow consumers, bounded buffers, chunk order, interruptions and equivalence, and that measure throughput and first-result latency.
Avoid:
- Treating a standard journey handoff as if it defined streaming.
- Planning cross-interlocking streaming without new declared runtime semantics (internal wagon streaming is possible).
- Inferring unimplemented orchestration behavior from this pattern, or treating it as a new runtime dispatch option.
Why: A standard journey handoff does not define streaming, so overlap is only sound when the protocol is explicit and its properties are preserved and tested.
