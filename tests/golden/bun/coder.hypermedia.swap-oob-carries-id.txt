Title: Give every hx-swap-oob element the id it swaps into
Given: Markup contains an element marked hx-swap-oob — an out-of-band fragment updating a region other than the requesting element's target (badge, flash region, count).
When: Any such element exists in the workspace or is written or edited, including edits touching only its id.
Then: The element carrying hx-swap-oob MUST itself carry an id (literal id="…" or JSX id={…}) naming the element it replaces.
Prefer:
- <div id="cart-count" hx-swap-oob="true">3</div> — swaps into #cart-count.
- Put the id on the oob element itself; htmx reads it from the element carrying the attribute.
- Smoke-test that the id matches an element existing in the current document.
Avoid:
- <div class="cart-count" hx-swap-oob="true">3</div> — no destination; dropped.
- Putting the id on a wrapper.
- Debugging server, route or response headers for "returned but page doesn't update" before checking the oob id.
Unless:
- Id supplied as a JSX expression (id={rowId}): binding present; resolution is a runtime concern.
- In-band hx-swap: swaps into hx-target, a selector, not an id.
Why: htmx matches oob elements to destinations by id; without one it silently drops them — no error, no warning, no swap. The server logs 200 and markup arrives, so this most frequent htmx silent bug sends people debugging code that is not wrong.
