Title: Every authored docs/ .adoc declares a non-empty :doc-id: and :status:
Given: An authored .adoc under docs/ (not docs/dist/), new or existing
When: docs are planned, written or validated
Then: Its header declares non-empty :doc-id: and :status: attributes.
Prefer:
- Declare both in the header above the first section: `= Shared Control Root` / `:doc-id: architecture.shared-control-root` / `:status: current`.
- Prefix doc-id with its area (`architecture.`, `purpose.`, `archive.`) so id and tree agree; readability only, unchecked.
- Status: `current`, `superseded` or `historical`.
Avoid:
- Declaring only one: id without status has unknown currency; status without id is a claim nothing can reference.
- Using a path as identity; doc-id is the only graph node id.
- Skipping header-less files; they are violations.
- Treating status as making archive/ honest: it cannot say superseded by what; the supersedes edge does (validated by planner.docs.graph-target-resolves). This rule only provides identity; it does not alone discharge the archival-currency issue.
Unless:
- Generated output beneath docs/dist/ (never scanned).
Why: Edges resolve only against declared doc-ids, so an undeclared document can be neither referenced nor found missing; status makes current-versus-historical readable.
