Title: Make every train structurally valid
Given: A train definition or registry entry is in scope for the plan (new or existing).
When: The planner authors, edits, reviews or validates that train, whatever field is touched.
Then: The train passes all seven structural validation rules: typed train_id, category as a declared field, spec file exists, participants declared, valid dependencies, domain:resource sequence artifacts, themes declared.
Prefer:
- Write train_id as train:{subject}:{slug}.
- Declare category in its own field with one of nominal|error|alternate|exception.
- Make sure the spec file exists at the train's declared path (create it or fix the path).
- List every participant the train uses in its participants list.
- Point every dependency at an existing, valid train_id.
- Name every artifact in the sequence as domain:resource.
- Declare every theme the train uses in its themes array.
Avoid:
- Untyped or free-form train ids that do not match train:{subject}:{slug}.
- Encoding the category as a digit inside the train identity.
- Declaring a spec path that has no file behind it.
- Using participants, themes or dependencies that are not declared / do not resolve.
- Sequence artifacts not in domain:resource form.
- Treating any of the seven checks as optional or advisory.
Why: Trains are consumed mechanically by the registry and validators; a train that breaks any structural rule cannot be addressed, resolved or checked reliably.
