Title: The docs corpus renders with asciidoctor
Given: The documentation corpus is being validated, whatever changed.
When: The docs validator runs over the corpus.
Then: The corpus MUST render with asciidoctor. A build failure attributable to a specific document is FAIL.
Prefer:
- Author docs that asciidoctor renders cleanly, and fix the document the build failure is attributed to
Avoid:
- Feeding docs/dist/** back in as a render input
- Scoring a crashed renderer, an unreadable tree or a missing toolchain as FAIL. Those are COULD_NOT_CHECK.
Unless:
- docs/dist/** is the render OUTPUT and is never an input to the render
Why: asciidoctor (Ruby) is the reference renderer because unresolvable internal references must be validation failures, and the Python options detect them weakly.
