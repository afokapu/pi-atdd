Title: Give every contract or telemetry leaf directory a tests/ subdirectory
Given: A directory under contracts/ or telemetry/ ({domain}/{resource}[/{category}]/) directly holds .schema.json or signal .json files (any signal type, e.g. metric/event definitions) — a leaf, existing or planned.
When: The planner authors or reviews a plan, wagon, acceptance or doc that adds, moves or lists a schema or signal, or checks those trees.
Then: Ensure that leaf directory contains a tests/ subdirectory holding the conformance tests for its schemas/signals.
Prefer:
- Place tests at contracts/{domain}/{resource}[/{category}]/tests/ or telemetry/{domain}/{resource}[/{category}]/tests/, next to the artifact.
- Include the tests/ directory in the same plan/wagon/acceptance that introduces the schema or signal.
Avoid:
- A .schema.json or signal .json in a leaf without a tests/ subdirectory.
- Collecting conformance tests in a central or parent directory instead of the leaf's own tests/.
- An empty tests/ created only to pass the check.
Why: The directory pattern is flexible, so each leaf with a schema or signal must ship its conformance tests alongside it for platform validation to verify the artifact against fixtures.
