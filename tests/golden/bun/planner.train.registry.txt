Title: Give every train both a registry entry and a spec file
Given: plan/_trains.yaml is the train registry, grouped by theme category; plan/_trains/ holds one spec file per train.
When: You add, change, rename, regroup, remove or validate any train, registry entry or train spec file.
Then: Ensure every train has both a registry entry in plan/_trains.yaml and a full spec at plan/_trains/{train_id}.yaml, so every registry entry has its spec file.
Prefer:
- Two-file pattern: registry entry (train_id, description, path, wagons summary) plus spec file (full workflow).
- Create the spec file in the same change as the registry entry, named from the train_id.
- Place each registry entry under its theme-category group: nominal, error, alternate or exception.
Avoid:
- A registry entry without its spec file, including a stale entry left after the spec is renamed or deleted.
- A spec file under plan/_trains/ with no registry entry.
- Spec filenames that do not match the registry train_id.
Why: Each train needs both files; validator SPEC-TRAIN-VAL-0003 fails the planner phase gate when a spec file is missing.
