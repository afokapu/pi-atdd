Title: Take component side, layer, type, suffix and weight from one canonical catalog entry
Given: A plan, WMBT or doc derives components, names file patterns or estimates effort, or the catalog is edited. The catalog (context.component-type-catalog) lists every type by side, layer, per-language suffix, description and weight, derived from the coder backend/frontend conventions.
When: You set a component's side, layer, type, URN side/layer, file pattern or weight.
Then: Take all of a component's values from one matching catalog entry: side, layer, type, the target language's suffix and the weight.
Prefer:
- Take URN side/layer values from the catalog structure; look entries up by side.layer.type.
- Pick the type whose description fits; estimate effort with catalog weights.
- Catalog edits: keep each type complete and derived from coder conventions; flag mismatches, never pick ad hoc.
Avoid:
- Ad-hoc types, layers, sides or weights; tweaking weights to shape an estimate.
- Mixing values across entries or languages.
Why: One canonical catalog keeps component derivation and effort estimates consistent with the coder conventions instead of ad hoc.
