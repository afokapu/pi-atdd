Title: Keep hand-authored plan unit specs schema-valid
Given: A plan session where you hand-author unit specs of any authorable kind.
When: You add or re-state a unit at Compose, or ratify the session before the lock.
Then: Keep every unit spec valid against its artifact schema: carried values well-formed (pattern, enum, type, additionalProperties) at Compose; kept units complete (required, minItems, minLength, minProperties) at Ratify.
Prefer:
- Fix malformed values when Compose refuses them; re-state the unit with add_unit (upserts by ref) as it fills in.
- Complete every kept unit before Ratify. Enforced (blocking) kinds by default: wagon, train, interlocking and the embedded acceptance shape — a kind blocks when its schema describes the artifacts atdd actually authors.
- For a kind with no schema, rely on its writer's validator; if nothing checks it, say so explicitly.
Avoid:
- Treating an unfinished draft at Compose as a defect, or a malformed value as fine because it is a draft.
- Ratifying with failing wagon, train, interlocking, embedded-acceptance or promoted-kind specs; a failure leaves the session unlocked.
- Reading a clean result from an ungoverned kind as approval.
Unless:
- Advisory kinds (schema drifted from what atdd authors; feature and wmbt by default) report and never block; findings ride on the unit through compaction and resurface at Ratify. A repo promotes a kind via plan.spec_validation.enforce in .atdd/config.yaml.
Why: atdd author is schema-valid by construction; plan specs are hand-written, so this layer must keep that guarantee. Silence that reads as approval is the defect this rule prevents.
