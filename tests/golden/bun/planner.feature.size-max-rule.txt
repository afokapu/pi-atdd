Title: Size each feature as max(WMBT-count size, footprint size)
Given: A feature has a WMBT count and, after decomposition, a footprint (components, events, new events).
When: You size or reclassify the feature.
Then: Set the feature's final size to max(WMBT-count size, footprint size).
Prefer:
- Pass 1 (planning): size by WMBT count only, to unblock decomposition — XS ≤5, S 6–10, M 11–20, L >20.
- Pass 2 (post-decomposition): compute the footprint, reclassify with the max rule, and gate M/L features.
- Keep final size at S or smaller; split or stage any larger feature before execution — decompose/stage an M feature (11–20 WMBTs), split an L feature (>20 WMBTs) immediately.
- Keep each feature within ≤8 components, ≤3 events, ≤3 new events.
Avoid:
- Taking the smaller of the two sizes or using only the WMBT count once a footprint exists.
- Sending an M or L feature to execution without splitting or staging it.
- Shaving WMBT counts or merging events/components on paper to land in S without actually reducing scope.
Why: Blended strategy: WMBT count alone sizes the feature early so decomposition is unblocked (Pass 1); once the footprint is known, the max rule reclassifies the feature so the larger of the two sizes governs and M/L features are gated (Pass 2).
