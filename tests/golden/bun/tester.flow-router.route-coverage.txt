Title: Prove every admissible interlocking route with an e2e test (Bun)
Given: An interlocking YAML declares admissible routes under `routes:`
When: a declared route has no e2e/**/*.ts test exercising it
Then: Write an e2e test that drives the route's guard-true inputs through production InterlockingRunner resolution, asserts the declared trainId was selected before execution, then executes that train via TrainRunner.
Prefer:
- Read route, guard and trainId; choose guard-true inputs that distinguish it from alternative routes.
- Place it at e2e/interlockings/<interlocking_slug>/<slug>.routes.test.ts.
- Call `new InterlockingRunner(...).resolveTrain(action, inputs)`; pass the selected train to TrainRunner and execute it.
- Also assert the route- or acceptance-specific execution outcome when one is declared.
Avoid:
- A routeId/trainId literal added only so lexical coverage sees it.
- A mock resolver or hand-built substitute for production route control.
- A descriptive assertion restating the plan without exercising resolution.
- Bypassing TrainRunner after proving only selection.
Unless:
- The YAML declares no `routes:` (registry index, generated projections).
- The route is already referenced by routeId/trainId in an e2e/**/*.ts test: not flagged, though a token-only test still fails review.
- The e2e rendering belongs to a non-Bun stack's own package.
Why: Each route is a production route-control branch; unexercised, it is a silent-green gap, and a bare token passes discovery while proving nothing. Strict: an admissible route without a covering e2e test blocks.
