Title: Declare `// Layer: assembly` in every journey spec header
Given: A browser/journey spec: a `*.e2e.ts` file run by Playwright, OR any test file whose header comments carry a journey marker (`// Train:`, `// Journey:`, `// URN: test:train:…`, `// URN: test:journey:…`), outside vendored/generated trees.
When: The spec exists in the scanned tree — whether newly created, already present, or edited in any way (header or body).
Then: The spec's header block MUST carry `// Layer: assembly`.
Prefer:
- Add `// Layer: assembly` to the header block.
- Treat a misnamed test file with journey markers as a journey spec and give it the assembly Layer.
Avoid:
- Omitting the Layer line from a journey spec header.
- Declaring a specific layer (e.g. presentation, application) on a browser test because it mainly touches that layer.
- Renaming a journey spec away from `*.e2e.ts` or stripping its journey markers to escape the check.
Unless:
- Vendored and generated trees (`node_modules`, `dist`, `build`, `_generated`) are never scanned.
Why: A browser test exercises the assembled application, not a layer of it; a missing or wrong Layer routes the result to the wrong layer bucket.
