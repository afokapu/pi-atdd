Title: Declare wagon features as an array of feature URN objects
Given: A wagon manifest declares its features (new, edited, or already existing).
When: The planner authors, edits, reviews or validates that wagon's `features` declaration.
Then: Declare the wagon's `features` as an array of objects each with a `urn` of the form `feature:{wagon-slug}:{feature-name}`; the legacy object map form is deprecated.
Prefer:
- Write features as `[{urn: feature:{wagon-slug}:{feature-name}}, ...]`, using this wagon's own slug as the middle segment.
- When already editing a wagon's features that still use the deprecated legacy object map, consider migrating it to the URN array format (recommendation only; the source sets no migration deadline).
Avoid:
- Introducing the deprecated legacy object map form `{feature-name: 'description'}` for the features declaration.
- Bare strings or objects without a `urn` key in the features array.
Why: The features declaration shape is a shared contract: the features-manifest rule and tooling consume the URN-array format, which keeps wagon-to-feature references traceable; the object map is the deprecated predecessor.
