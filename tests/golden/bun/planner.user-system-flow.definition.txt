Title: Advisory semantic anchor (not directly enforced): read and author a train as one linear end-to-end journey ending in one terminal contract
Given: a planner is decomposing a domain into trains, or interpreting/classifying an existing journey as a train
When: they define, reshape or classify a train
Then: Use this advisory definition. It enforces nothing directly; the constraint/rule nodes that require it do the enforcing. A train names exactly one executable end-to-end journey: a strictly linear, ordered sequence of steps across declared wagons, from a declared initial input to exactly one terminal contract.
Prefer:
- A full journey the domain can run end to end, not a fragment.
- Strictly sequential steps between declared participants, with one coherent outcome, at least 2 wagons and ideally 3-7.
- Declare the initial input and the artifacts moved from step to step.
- Have the terminal step declare exactly one primary artifact, and derive the train's family from it.
Avoid:
- Loops, routes or branching inside a train.
- Bundling several journeys or outcomes into one train.
- Multiple terminal contracts, or a family that disagrees with the terminal contract.
- Specifying how the journey runs or what runtime state it holds; those are coder/tester concerns.
- Treating this anchor as a separately enforced rule. Findings come from the constraint/rule nodes that require it.
Why: A train names WHAT journey the domain must support. This anchor gives that a stable meaning, and the enforceable nodes that require it (linearity, scope, terminal contract, family) do the checking.
