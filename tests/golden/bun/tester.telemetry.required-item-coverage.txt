Title: Bind every required telemetry item to a test via a `// Telemetry:` header
Given: An acceptance with required telemetry lists a concrete URN that exists in the tracking plan (a required item)
When: Required items, the tracking plan, or test files' `// Telemetry:` headers are added, changed or removed
Then: Ensure at least one test file binds each required item with a `// Telemetry: <urn>` header.
Prefer:
- Add a telemetry test whose header names the acceptance (`// Acceptance: <acc-id>`) and the item (`// Telemetry: <telemetry-urn>`), and whose body proves the item is emitted.
Avoid:
- Leaving a required item planned and implemented but untested.
- Adding a `// Telemetry:` header to a test that does not exercise the item just to close the gap.
Unless:
- Diagnostic logs and internal spans an acceptance does not require need no dedicated test — only required items are covered by this closure.
- Inert until the repository adopts this rule family.
Why: Evidence leg of the traceability tripod (planned, implemented, tested): the coder rule binds the implementation, this binds the proof. A required item no test covers is a plan nobody can rely on.
