Title: An absent change set is COULD_NOT_CHECK (blocks), never 'nothing undeclared'
Given: A plan's work has a recorded documentation declaration.
When: core supplies no change set at all, as opposed to an empty one.
Then: The docs check returns COULD_NOT_CHECK, which blocks. It never reports 'nothing undeclared'.
Prefer:
- Read an empty change set as 'nothing changed' (permits), and an absent change set as COULD_NOT_CHECK (blocks).
Avoid:
- Treating an absent change set as an empty one, or reporting 'nothing undeclared' when no change set was supplied.
Unless:
- No declaration is recorded at all. That case belongs to core, not to this rule.
Why: An ABSENT change set is not an empty one. Without a change set, the check is in no position to claim that nothing is undeclared. An empty change set is core saying that nothing changed, which is actionable. The two stay distinct for the same reason NOT_APPLICABLE and COULD_NOT_CHECK do (spec 2 §3).
