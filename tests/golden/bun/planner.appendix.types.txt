Title: Type every appendix as one of the six recognized appendix types
Given: You are creating a wagon, WMBT, feature, component or acceptance and have supplementary content (designs, data, docs, diagrams, recordings) attached or to attach as an appendix.
When: You name, classify, or read an appendix artifact.
Then: Classify it as exactly one of the six recognized appendix types (mockup, spreadsheet, document, diagram, audio, video), using a file extension from that type's list.
Prefer:
- mockup [PNG, JPG, JPEG, SVG, GIF]: visual designs, UI mockups, wireframes, prototypes; informs component structure and harness selection. Use cases: UI screen designs → component structure during feature decomposition; user flow diagrams → WMBT decomposition and when/must/then statements; visual states (loading, error, success) → harness selection (visual, e2e); responsive variants (mobile, tablet, desktop) → acceptance criteria.
- spreadsheet [XLSX, CSV, TSV]: data models, calculations, business rules, requirements matrices; informs domain model and acceptance criteria. Use cases: complex pricing/tax calculation logic → domain model and business rules; data validation rules → acceptance criteria; requirement traceability matrices → feature clustering; test data sets → acceptance given/when sections.
- document [PDF, DOCX, MD, TXT]: specifications, research findings, technical guides, PRDs; informs wagon description and component contracts. Use cases: product requirements documents → wagon description and scope; technical specifications → component contracts and responsibilities; user research findings → WMBT scenarios and pain points; API documentation → integration acceptance criteria.
- diagram [PNG, SVG, MERMAID, DRAWIO]: architecture diagrams, ERDs, sequence diagrams, flowcharts, state machines; informs 4-layer structure and integration points. Use cases: system architecture diagrams → 4-layer structure and component boundaries; entity-relationship diagrams → domain model and data structures; sequence diagrams → WMBT when/then steps and integration points; state machine diagrams → component behavior and state transitions.
- audio [MP3, WAV, M4A, OGG]: user interviews, voice notes, recorded requirements sessions; informs WMBT scenarios and pain points. Use cases: user interview recordings → extracting pain points and requirements; stakeholder requirement sessions → wagon scope and priorities; voice memos → context and clarifications; accessibility testing feedback → a11y harness criteria.
- video [MP4, MOV, WEBM, AVI]: screen recordings, demos, walkthroughs, user testing sessions; informs feature parity and reproduce steps. Use cases: demo of existing system behavior → feature parity requirements; user testing sessions → pain points and interaction patterns; tutorial videos → understanding complex workflows; screen recordings of bugs → WMBT reproduce steps.
Avoid:
- Appendix filenames lacking the artifact-name and type segments (e.g. `notes.png`).
- Inventing a type outside the six (e.g. `auth_screenshot_login.png` — 'screenshot' is not a recognized appendix type; a screenshot of a UI is a mockup).
Why: A fixed appendix taxonomy lets the planner agent recognize supplementary content, choose the right multimodal reading strategy, and map each artifact to the planner output it enriches.
