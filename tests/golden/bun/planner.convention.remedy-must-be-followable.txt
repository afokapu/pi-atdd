Title: Name only existing files and live CLI verbs in a convention node's operative prose
Given: Any convention node in the toolkit checkout — existing and unchanged, or one you author/edit — whose operative prose (fix_hint, operational_guidance, normative_text, statement, term text, notes, description) names a repo path or CLI verb
When: the checkout is validated; also when you write such a node or plan to rename/remove a file or retire a verb it quotes
Then: Every path named in operative prose must exist in the checkout and every CLI verb named must still resolve — a fix_hint is an executable promise.
Prefer:
- Absent path: correct it to the real location, or drop the pointer if the thing no longer exists.
- Retired verb: replace it with its live replacement (e.g. `atdd issue <N> --status <PHASE>` → `atdd coach transition <N> <PHASE>`; `atdd issue open` → `atdd coach issues open`).
- When retiring a verb, record it with its live replacement.
- When a plan renames a file or removes a verb, include updating every node that quotes it.
Avoid:
- Half-repairs: swapping an absent path for one that is merely plausible — that produced this defect.
- A remedy saying only "that verb is gone" without the live verb — itself unfollowable.
- Describing a retired path in present tense — a defect, not a record.
Unless:
- Provenance (`source.legacy_path` + `legacy_sha`) — pointing at a deleted file is what provenance is.
- Illustrative paths in `examples`/`values` blocks — fictional by design.
- Schematic `Formula:` templates — segments are positions, not directories.
- A path named as an EXCLUDED mechanism ("no X") — a statement of absence.
- A conditional reference ("if it exists", "when present").
- Gitignored runtime state (via `git check-ignore`).
- A path the node declares RETIRED in past tense — a historical record.
Why: A fix_hint is read exactly when the reader is blocked; a missing file or dead verb sends them nowhere. Historically nothing read fix_hints, so a verb removal and a validator rename left every quoting hint stale.
