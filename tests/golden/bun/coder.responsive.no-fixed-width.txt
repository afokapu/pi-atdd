Title: Keep width and min-width within the smallest viewport
Given: A stylesheet, `<style>` block, `style` attribute or JSX `style` object (in any file) outside vendored/generated trees
When: it contains a `width` or `min-width` declaration (JSX: `width` / `minWidth`)
Then: The value (rem/em at 16px) MUST NOT exceed the smallest width in `atdd-bun.yaml` `frontend.viewports` (default 375px).
Prefer:
- Make content fluid at small viewports, usually `width: 100%` plus an appropriate `max-width`, not an oversized fixed `width`/`min-width`.
- Express wide layouts with `max-width`, percentages, or wrapping layouts.
- During GREEN: fix only the element responsible for the current overflow; reuse existing layout containers and responsive primitives.
- During GREEN: keep the intended large-screen cap while letting the element shrink.
- Config (frontend_settings): `frontend.viewports` = widths responsive specs render at (smallest bounds fixed widths); `frontend.breakpoints` = widths media queries may use.
Avoid:
- Hiding overflow to mask an oversized element.
- Removing useful `max-width` constraints merely to pass the detector.
- Redesigning unrelated layout.
Unless:
- `max-width` is not judged; it is how wide layouts are bounded.
- Custom property definitions (`--page: 1200px`) are tokens, not judged.
- `node_modules`, `dist`, `build`, `_generated` are never scanned.
Why: An element wider than the screen forces horizontal scrolling on every phone.
