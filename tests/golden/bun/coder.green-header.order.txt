Title: Order present header fields as URN -> Tested-By -> Runtime -> Purpose
Given: A file checked by the Bun realization carries a URN traceability field plus any of Tested-By, Runtime, Purpose
When: the file exists in the checked codebase, regardless of whether its header was edited in the current change
Then: The present header fields MUST appear in the order URN -> Tested-By -> Runtime -> Purpose.
Prefer:
- During GREEN repair: reorder only the header lines needed to restore the canonical sequence.
- During GREEN repair: keep the existing field values unless another convention proves one is wrong.
- During GREEN repair: preserve unrelated comments.
Avoid:
- Do not broaden: rewriting identifiers, acceptance bindings, runtime, or purpose merely while fixing order.
- Do not broaden: moving implementation code to satisfy a header-order finding.
- Adding a missing field just to silence this rule — absence is each field's own rule, not this one.
Unless:
- The file has no URN — it is skipped; there is nothing to order against.
- A field is absent — it is not considered; presence is each field's own rule.
- Other comment lines are interleaved between the fields — this is allowed.
Why: A fixed order (identity, then proof, then execution context, then intent — each field answering the question the previous one raises) lets a reader, human or tool, know where to look without parsing; it is the same order in Python, Vite and Bun.
