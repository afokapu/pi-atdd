Title: An unexamined docs corpus is COULD_NOT_CHECK, never PASS or FAIL
Given: The docs validator is run over the corpus.
When: The toolchain is absent, the renderer crashes, the tree is unreadable, or a build failure cannot be attributed to a specific document.
Then: The verdict MUST be COULD_NOT_CHECK, which BLOCKS. It is reported as a named state that reaches the report: never PASS, never FAIL, never NOT_APPLICABLE.
Prefer:
- For COULD_NOT_CHECK, install the toolchain (gem install asciidoctor) and re-run, rather than suppressing the verdict
Avoid:
- Treating a missing asciidoctor as a clean corpus. It is an unexamined one.
- Collapsing COULD_NOT_CHECK (blocks) into NOT_APPLICABLE (permits) or PASS
- 'Fixing' COULD_NOT_CHECK by making the capability return PASS when the renderer is absent. That is the #1745 defect, re-committed.
- Turning an unresolvable lookup into an empty clean result
Why: The verdict distinction is the point of this rule and the thing most likely to be got wrong. This repository has had the bug in at least three places (#1745, #1774, #1716).
