Title: Place every feature test beneath its feature and test-kind directory
Given: The plan models at least one wagon, feature or WMBT, and tests exist beneath <test_root> (atdd-bun.yaml `topology.test_root`, default `tests/wagons`), outside vendored/generated trees.
When: You add, move or keep any test beneath <test_root>, or change the plan — existing tests are in scope too.
Then: Every test beneath <test_root> lives beneath `<test_root>/<wagon>/features/<feature>/{unit,contract,integration}/`, in the directory of the feature it tests and the kind of test it is.
Prefer:
- Move the test beneath its feature under unit/, contract/ or integration/ according to the kind of test it is, and add the test URN and Acceptance header.
Avoid:
- Placing tests in a path that does not state their feature and test kind (unit/contract/integration).
- Leaving a test without `URN: test:{wagon}:{feature}:{acceptance}` matching its wagon/feature path (mandatory; split rule test-urn-header).
- Leaving a test without `Acceptance: acc:{wagon}:{acceptance}`, or binding one that does not exist or is not declared by a WMBT that the test's own feature explicitly lists (mandatory; split rule test-acceptance-binding).
Unless:
- Vendored and generated trees (`node_modules`, `dist`, `build`, `_generated`) are never scanned.
Why: A test proves an acceptance only when it names one that exists; its path says which feature and which kind of test it is.
