Title: RED tests assert behaviour, not existence
Given: A Bun test file whose declared Phase is RED
When: any it() case exists in it (authored, changed, or checked)
Then: Every case MUST contain at least one behavioural assertion — on what the code DOES, the one that fails before the implementation exists — not only existence checks (toBeDefined/toBeTruthy/toBeFalsy/toBeNull/toBeUndefined), and never no assertion.
Prefer:
- Build the case from the bound Acceptance / @covers, not the code you expect to write: pick the one behaviour it proves; derive the expected outcome from its Then.
- Honor declared harness/execution context; enter through the narrowest boundary that still proves the behaviour.
- Turn the When into one primary action; create only the Given state it needs.
- Assert the observable consequence named (exact error, status/body, state change, emitted item, other declared outcome) — a witness that turns red if the behaviour is removed, inverted or stubbed: `expect(() => checkout({ items: [] })).toThrow("CART_EMPTY")`, not `expect(checkout).toBeDefined()`.
Avoid:
- Existence-only assertions such as `toBeDefined()` as the behavioural proof.
- Inventing a convenient assertion from the current implementation.
- Moving inward to an easier seam that stops exercising what the acceptance claims.
- Mocking/substituting the subject or collaboration being proved.
- Asserting incidental implementation details instead of the declared outcome.
- Computing the expected value with the production code, or copying its algorithm into the test.
- Adding an unrelated behavioural assertion merely to clear the detector.
- Broadening one case to prove several unrelated behaviours.
Unless:
- Declared phase is not RED — only RED-phase files are scanned.
- No declared phase — skipped; that is phase-declared's finding.
- Detector only: a case mixing existence and behavioural assertions is not flagged.
Why: RED must build the smallest executable proof of the declared acceptance before implementation; an existence check passes once a stub is exported, leaving the acceptance unproven.
