Title: Reference only registered contracts as interlocking message payloads
Given: An interlocking artifact has messages that reference payload contract identities.
When: The plan reaches CONFIRM (any referenced identity is checked, changed or not).
Then: Every payload contract identity referenced by an interlocking message must resolve to an authored/registered entry in the contracts registry (contracts/_contracts.yaml), not merely to a file that glob-matches.
Prefer:
- Look up the identity in the contracts registry, the single source of truth for identity -> path -> theme -> producers -> consumers, and reference an identity that is a member of it.
- If the needed contract is not yet registered, plan its authoring and registration as part of the work before referencing it.
- When a registry entry is removed or renamed, update the interlocking messages that reference it.
Avoid:
- Pointing the payload at a contract file that merely exists or glob-matches without a registry entry.
- Inventing a contract identity in the interlocking that no registry entry backs.
Why: The contracts registry is the single source of truth for identity -> path -> theme -> producers -> consumers; a glob-matching file is not sufficient to count as a registered contract.
