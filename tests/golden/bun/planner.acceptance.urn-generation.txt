Title: Build acceptance URNs as acc:{wagon}:{wmbt_id}-{harness}-{NNN}[-{slug}] via URNBuilder.acceptance
Given: A planning artifact declares an acceptance tied to a WMBT within a wagon and executed by a specific harness.
When: The planner assigns or changes that acceptance's URN.
Then: The URN must be acc:{wagon}:{wmbt_id}-{harness}-{NNN}[-{slug}], produced via URNBuilder.acceptance(wagon_id, wmbt_id, harness_code, seq, slug=None).
Prefer:
- Call URNBuilder.acceptance(wagon_id, wmbt_id, harness_code, seq, slug=None) rather than concatenating strings by hand.
- Use colons only for hierarchy (acc:wagon:wmbt_id) and dashes for the facet cluster (-harness-NNN[-slug]).
- Use a kebab-case wagon, a WMBT id of step code + 3-digit seq (e.g. C004), an UPPERCASE harness code, a per-harness sequence 001-999 (never 000), and an optional kebab-case slug for readability.
- WMBT step letter must be one of D L P C E M Y R K; harness code must be one of UNIT, HTTP, EVENT, WS, E2E, A11Y, VIS, METRIC, JOB, DB, SEC, LOAD, SCRIPT, WIDGET, GOLDEN, BLOC, INTEGRATION, RLS, EDGE, REALTIME, STORAGE, SMOKE. Full pattern: ^acc:[a-z][a-z0-9-]*:[DLPCEMYRK][0-9]{3}-(UNIT|HTTP|EVENT|WS|E2E|A11Y|VIS|METRIC|JOB|DB|SEC|LOAD|SCRIPT|WIDGET|GOLDEN|BLOC|INTEGRATION|RLS|EDGE|REALTIME|STORAGE|SMOKE)-[0-9]{3}(?:-[a-z0-9-]+)?$
Avoid:
- The legacy format acc:{wagon}:{nnn}:{acceptance_id} (e.g. acc:authenticate-user:001:AC-EXEC-201) — it is being migrated away.
- Dropping the WMBT id or harness code from the URN, or sharing one sequence across harnesses.
- Lowercase or unlisted harness codes, step letters outside D/L/P/C/E/M/Y/R/K, or non-kebab slugs.
Why: The URN is the canonical id of an acceptance: it makes the WMBT tie explicit, bakes in harness visibility for routing, keeps a per-harness sequence, and allows an optional readability slug.
