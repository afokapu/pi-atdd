Title: Use kebab-case for logical identifiers and snake_case for plan filesystem paths
Given: A planner writes a logical identifier (any URN, slug field or YAML ref, in any file) or a plan filesystem artifact (directory, manifest file, feature file)
When: The planner writes or edits the identifier, or creates or renames the path
Then: Write logical identifiers in kebab-case. Name filesystem artifacts in snake_case: plan/{wagon_dirname}/, manifest plan/{dirname}/_{dirname}.yaml, features plan/{wagon_dirname}/features/{feature_name}.yaml.
Prefer:
- Follow the source example: feature:authenticate-identity:verify-session -> plan/authenticate_identity/ + _authenticate_identity.yaml + features/verify_session.yaml
- Name the manifest after the directory, not the slug: _{dirname}.yaml
Avoid:
- Hyphenated directory or feature file names under plan/ because the URN uses hyphens
- Underscored values in any URN, slug field or YAML ref
- Naming the manifest after the kebab slug (_{slug}.yaml)
Why: Consistent filesystem naming reduces conversion complexity and keeps logical (kebab) and physical (snake) identifiers clearly separate.
