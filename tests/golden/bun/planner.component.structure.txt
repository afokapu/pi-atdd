Title: Emit every generated component with its complete required structure
Given: The planner is generating components
When: it emits any generated component
Then: Emit it with: URN component:{wagon}.{feature}.{business_capability}.{side}.{layer}; a required parent feature equal to the input feature URN; description 'Handles {business_capability} for {feature} using {layer} patterns'; consumed events taken from feature.ioSeeds.consume filtered by the component's role and produced events from feature.ioSeeds.produce filtered by its capability, at most 3 each; dependencies = the other components in the same feature plus external dependencies.
Prefer:
- Use {side}, not the older {tier}, as the URN segment naming the side of the system.
Avoid:
- Omitting the parent feature, or exceeding 3 consumed or 3 produced events (e.g. 5 produced events).
- Free-form descriptions, unfiltered copies of all ioSeeds events, or dropping either same-feature components or external dependencies from the dependency list.
- Treating a missing input feature URN as making this rule inapplicable; the parent feature is required, so emitting without it is a violation.
Why: Pinning down the full required shape — parent feature, description, bounded events, dependencies — ensures every component the planner emits is complete and consistently structured for downstream phases.
