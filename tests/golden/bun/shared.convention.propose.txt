Title: Raise convention gaps and misfires as evidence-backed proposals through the governed path
Given: An agent in any profile meets a situation no active convention covers, or an active convention that misfires
When: it encounters that gap or misfire (including a gap measured in an experiment)
Then: Record a convention proposal — situation, concrete evidence, proposed rule, target `<profile>.<area>` — where the coach collects proposals for the work.
Prefer:
- First check whether an existing convention covers it; point to it instead of proposing.
- Evidence = an observed failure a reader can check: failed/returned review, missed trap or acceptance, same mistake repeated across tasks or agents, a convention that fired where it does not apply or stayed silent where it should, or a measured experiment gap (attach run evidence).
- Profile ∈ planner, tester, coder, reviewer, coach, shared (shared only if every profile must receive it). For a change, name the convention id and quote the misfiring part.
- Continue the assigned task under the conventions active now.
- Coach: collect proposals, merge duplicates. Author: draft in convention format; independent auditor checks. Owner: approve or decline. Approved → new convention in its profile family; declined → recorded as declined with the reason.
Avoid:
- Creating, editing, renaming, disabling or deleting an active convention (anything the catalog currently loads: file, id, relationships, selectors).
- Applying the proposed rule to the task that raised it, or treating it as approved before the owner approves.
- Proposing from preference, style or hypothetical risk without an observed failure.
- Filing without target profile and area.
Unless:
- Exception to avoid[0] only: a task whose explicit, owner-approved purpose is to change the catalog (e.g. a convention rewrite or rename) edits conventions as its deliverable, but still goes through author, auditor and owner review before the change is active.
- Reporting that an active convention could not be followed is not a proposal and is always allowed: state the blocker in the report and continue or stop as the other active conventions require.
Why: Editing an active convention for the current task removes its guard, and preference-driven rules add noise weaker models then follow; one governed, review-only path keeps the catalog small, evidence-backed and owned.
