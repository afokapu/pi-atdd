Title: Declare the test's real ATDD phase
Given: A test file that carries a URN
When: you write, bind or edit that test file
Then: Declare `// Phase:` with exactly one of RED, UNIT, SMOKE, E2E, matching what the test actually does and the proof boundary it exercises.
Prefer:
- Derive the phase from the test's role: RED = current acceptance proof intentionally failing first; UNIT = isolated local behavior; SMOKE = real assembled path/infrastructure with operator-observable evidence; E2E = end-to-end journey through the assembled system.
- After declaring, check the test meets what that phase now requires: a RED test must fail first and must assert behaviour; a SMOKE test must assert something operator-observable and must not substitute collaborators. Confirm the phase matches the boundary really exercised.
Avoid:
- Omitting the phase (silently exempts the test from every phase-gated rule).
- Choosing a weaker label to silence a phase-gated rule; phase selection is part of the proof contract.
- Relabelling a real-path SMOKE or assembled E2E proof as UNIT to permit substitution.
- Labelling a passing or vacuous case RED because a RED marker is easy to add.
- Inventing a new phase value in an extension; the vocabulary is fixed by core.
Unless:
- The file carries no URN (such files are skipped).
Why: The phase is not documentation: it selects which other rules apply (e.g. RED must fail first and assert behaviour; SMOKE must assert something operator-observable and must not substitute collaborators), so a perfectly identified test without the right phase is ungoverned or governed by the wrong obligations.
