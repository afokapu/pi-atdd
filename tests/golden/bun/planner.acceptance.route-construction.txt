Title: Build route.sequence as ordered {layer}.{action} steps
Given: An acceptance with a route.sequence.
When: The planner writes or changes route.sequence.
Then: Write route.sequence as ordered {layer}.{action} transitions from the route_step vocabulary, flowing presentation -> application -> domain -> integration as needed (include only the layers the scenario uses; a route triggered from an external integration may start at integration, as in the event flow).
Prefer:
- Command: presentation.command -> application.use_case -> domain.validate -> integration.persist.
- Query (skips domain): presentation.query -> application.query -> integration.read.
- Event (starts at integration): integration.call_external -> application.aggregate -> domain.mutate -> integration.persist.
- Steps: presentation.{command,query,display}; application.{use_case,query,aggregate}; domain.{create,validate,mutate,policy}; integration.{read,persist,call_external}.
Avoid:
- Free-form step names or layers outside presentation/application/domain/integration.
- Listing steps unordered or in an order that does not reflect the actual sequence of transitions; do not reject or reorder an integration-initiated route like the event flow just because it begins at integration.
- Padding the route with layers the scenario does not need.
Why: A fixed {layer}.{action} vocabulary makes the layer flow behind each acceptance explicit and mechanically checkable.
