Title: Name every produced or consumed artifact theme-first
Given: A produced or consumed artifact/contract identity exists (new, renamed or pre-existing)
When: Identities are validated at CONFIRM
Then: The identity must be theme-first: it parses as {theme}(:{category})*:{aspect}(.{variant})?, every colon- or dot-separated token is kebab-case, and the leading theme is declared in plan/_themes.yaml.
Prefer:
- Start the name with a theme declared in plan/_themes.yaml, then optional categories, then the aspect, then an optional .variant (e.g. commons:identifiers.uuid, commons:ux:foundations:color, orders:checkout.submitted, inventory:stock)
- Use lowercase kebab-case for every token between colons and dots
- If no fitting theme exists, declare it in the canonical theme map first rather than inventing it inline
Avoid:
- Using a leading theme that is not declared in plan/_themes.yaml (e.g. undeclared:result)
- Uppercase or non-kebab tokens (e.g. Bad:Theme)
- Names without a theme:aspect colon structure, such as dot-only names (e.g. gesture.raw)
Why: Artifact identities are the join keys between producers and consumers and contract paths mirror them; a fixed theme-first grammar anchored to a canonical theme map keeps them parseable, unambiguous and consistently located.
