Title: Keep Cargo runtime values and artifact data out of interlockings
Given: A planner artifact contains an interlocking.
When: You write, change or review that interlocking's contents.
Then: The interlocking selects routes and declares payload contract identities, and contains no Cargo runtime values and no artifact data.
Prefer:
- Reference each payload by its contract identity and let the route carry the actual Cargo at runtime.
- Keep concrete values and artifact content in the Cargo/artifact layer where they are produced.
Avoid:
- Inlining Cargo runtime values (sample or concrete payload values) in any interlocking field.
- Copying artifact data into an interlocking to 'document' or pre-fill a route.
- Hiding runtime values in nested or renamed fields to dodge the validator.
Why: Interlockings are route-selection and contract-identity declarations; putting Cargo runtime values or artifact data in them couples routing to specific payload instances and blurs the boundary between plan and runtime data.
