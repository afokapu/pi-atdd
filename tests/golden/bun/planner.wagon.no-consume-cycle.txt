Title: Keep the cross-wagon produce/consume graph acyclic
Given: A plan's wagons declare produce/consume entries by artifact NAME, forming a directed graph with an edge producer-wagon -> consumer-wagon whenever a name produced by one wagon is consumed by another.
When: You author, edit or review any plan containing such wagons, whether or not your change touches produce/consume entries.
Then: Ensure the name-keyed wagon graph is acyclic: no strongly-connected component may contain more than one wagon, including cycles that already existed.
Prefer:
- Before adding an edge producer B -> consumer A (A consumes a name B produces), check by artifact name whether a path A -> B already exists; if it does, the new edge would close a cycle.
- When a loop exists, restructure wagon boundaries or artifact ownership so dependencies flow one way.
Avoid:
- Reasoning about wagon dependencies via the contract field; it is nullable corpus-wide, so edges must be keyed on the produce/consume artifact name.
- Mutual or transitive produce/consume loops between two or more wagons (a consume_cycle).
- Hiding a loop by nulling or renaming the contract field while the artifact names still loop.
Why: A cross-wagon produce/consume cycle means no wagon in the loop can be delivered before the others; the graph must be a DAG so wagons can be ordered. Artifact names are the only reliable key because contract is nullable.
