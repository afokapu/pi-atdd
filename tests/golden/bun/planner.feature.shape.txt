Title: Give every feature YAML a urn, a status, and a non-empty acceptance section
Given: A file is a feature YAML (newly authored, edited, or already existing)
When: the feature YAML is written, reviewed, or validated
Then: The feature YAML declares a urn, a status, and a non-empty acceptance section.
Prefer:
- Fill in urn, status, and at least one acceptance entry when first creating the feature file.
- Keep the acceptance section populated when restructuring a feature.
- When an existing feature YAML is found missing any of these fields, bring it into shape rather than treating pre-existing files as exempt.
Avoid:
- Leaving acceptance as an empty list/map or placeholder just so the key exists.
- Omitting urn or status on the assumption they are inferred from the file path or wagon.
Why: Downstream planning artefacts — component URNs, component derivation from ioSeeds/WMBTs, and wagon/WMBT coverage checks — presuppose a well-formed feature with these fields.
