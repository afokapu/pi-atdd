Title: Give every authored doc a corpus-unique doc-id
Given: The docs/ corpus: every authored .adoc, archive/ included, docs/dist/ excluded.
When: Any declared `:doc-id:` is shared by another doc — newly introduced (create, copy, move, archive) or pre-existing and found by validation.
Then: Ensure no two authored documents in the corpus declare the same `:doc-id:`.
Prefer:
- Archived and replacement docs get DIFFERENT ids; the new one (`:status: current`) declares `:supersedes: <archived-id>`; the archived one is `:status: superseded`.
- archive/ shares the id space on purpose: choose archived ids (e.g. `archive.<date>-<slug>`) that cannot collide.
Avoid:
- Re-using a current id in archive/: the resolver cannot tell superseding from superseded doc, so `:supersedes:` fails exactly where it is needed.
- Deleting a doc to fix a duplicate; preserving history is the point.
- Copying a template doc without changing its `:doc-id:`.
Unless:
- Generated output beneath `docs/dist/` is never scanned.
- Docs with no `doc-id` belong to `planner.docs.identity-required`; only declared ids are compared.
Why: Uniqueness makes doc-id an identity, not a label, so every edge resolves to one target; a duplicate leaves `:supersedes: architecture.foo` unable to say which `architecture.foo` it means.
