Title: Advance plan-session stages only through their exit gates
Given: An atdd plan session runs the gated stages Intent -> Attach -> Compose -> Ratify, then author -> verify -> modify.
When: The planner is about to move the session to the next stage.
Then: Advance only when the current stage's exit state holds: Intent = the main job is kept; Attach = sources and plan/ state are captured; Compose = the candidate decomposition is convention-shaped; Ratify = the operator has locked the decomposition.
Prefer:
- Talk freely within a stage; the gate defines only the exit state, not a script.
- Backtrack when useful: a pivot may reopen an earlier stage.
- Name stages by what the operator is deciding, not by what the tool is doing.
Avoid:
- Authoring anything before the Ratify gate; Ratify is the conversational->deterministic boundary (its rule is planner.plan.confirm-before-author).
- Treating session stages and the WMBT job steps of steps.convention as one system or one vocabulary.
- Advancing a stage when its exit state does not hold.
Why: Gating on exit state keeps the decomposition dialogue flexible while guaranteeing nothing deterministic is authored until the operator has ratified a convention-shaped decomposition.
