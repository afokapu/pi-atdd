Title: Connect every rendering app component to the design system
Given: A repo with a design root and a .tsx/.jsx app component outside it that renders markup
When: any such component is assessed (new, edited, or untouched)
Then: It MUST import at least one design-system element (token, primitive, component, or template) from the design root, so no UI surface is disconnected from the shared system.
Prefer:
- Compose UI from the existing design-system template, component, or primitive that owns the required role.
- During GREEN: reuse the nearest existing design-system surface; add only the connection the current rendered behavior requires.
- During GREEN: if no suitable surface exists, introduce the smallest design-system component that expresses the current need.
Avoid:
- A meaningless design import merely to satisfy connectivity.
- A generic component library for hypothetical callers.
- Redesigning the screen or migrating unrelated markup.
Unless:
- No design root in the repo (not judged).
- Test files (*.test.*, *.spec.*), vendored/build dirs (never scanned).
- Non-rendering modules: routes, handlers, data (not judged).
Why: A screen built without the system is where the next one-off style lands. Requiring one design import makes the connection explicit and reviewable.
