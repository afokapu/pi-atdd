Title: Plan batched or fused work only where it preserves logical results and boundaries
Given: a plan has repeated homogeneous operations, database queries, vectorizable computation or repeated setup
When: the planner decides whether to batch or fuse it
Then: combine compatible calls or computations to amortize I/O, setup, serialization or scheduling overhead only without changing accepted logical results, preserving item identity, failure independence, transaction/authority boundaries, order and resource limits.
Prefer:
- Keep batching internal to a wagon (the normal case); no journey or interlocking schema change is needed.
- Write acceptances for mixed outcomes, batch boundaries, item-result mapping and equivalence; measure throughput and tail latency.
Avoid:
- Fusing across wagon ownership merely to reduce calls.
- Batches that lose per-item results, couple failures, cross transaction boundaries or reorder items.
- Inferring unimplemented orchestration behavior from this pattern, or treating it as a new runtime dispatch option.
- Treating this advisory guidance as independent enforcement; existing plan and source validators still apply.
Why: Batching amortizes per-call overhead but helps only if callers keep the same per-item results and isolation.
