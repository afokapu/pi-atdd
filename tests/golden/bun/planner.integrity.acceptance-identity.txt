Title: Give every embedded acceptance an acc: identity
Given: A WMBT outside vendored/generated trees embeds one or more acceptances — new, edited, or untouched.
When: An embedded acceptance is encountered in a scanned WMBT.
Then: Every embedded acceptance is an object whose `identity.urn` starts with `acc:`.
Prefer:
- Give the acceptance `identity: { urn: acc:<wagon>:<id> }`, using the owning wagon and a stable acceptance id.
Avoid:
- Embedding an acceptance as a bare string or an object without `identity.urn`.
- An `identity.urn` that uses any prefix other than `acc:`.
- Leaving pre-existing embedded acceptances without an `acc:` identity because you did not edit them.
Unless:
- The file is in a vendored or generated tree (`node_modules`, `dist`, `build`, `_generated`) — these are never scanned.
Why: Tests bind acceptances by their acc: identity; an acceptance without it can never be proven.
