Title: Give every train a typed kebab-case train_id
Given: The change set contains a train definition document: a YAML file whose purpose is to define one train (its own train_id, title and contents), wherever it currently sits. Files that only reference trains, and non-train auxiliary files, are not train documents.
When: the planner creates, edits, renames or moves it, or changes its train_id, title or file location
Then: Set train_id to the typed identity train:{subject}:{descriptive-name}, with both subject and descriptive name in kebab-case.
Prefer:
- Mandatory, not optional: store the file flat at plan/_trains/{train_id}.yaml, filename taken from the train_id.
- Mandatory, not optional: write the title in Title Case.
Avoid:
- Untyped ids missing the train: prefix or the {subject} segment.
- camelCase, snake_case, spaces or uppercase in subject or descriptive name.
- Titles not in Title Case (e.g. lowercase or a copied kebab-case id).
- Nested subdirectories under plan/_trains/, train files outside plan/_trains/, or a filename that differs from the train_id.
- Renaming or adding train identity fields to README, registry or other non-train files.
Why: A single typed, predictable train_id gives each train one identity from which its file path and references can be derived mechanically.
