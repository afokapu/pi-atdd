Title: Keep every TypeScript file reachable from a structural root
Given: A TS/TSX file in a scan root that contains a structural root
When: The tree is scanned (any file, existing or changed, including package.json script edits)
Then: Every TypeScript/TSX file MUST be reachable, forwards or backwards, from a structural root through runtime (non-type-only) import edges.
Prefer:
- First decide if the file should exist at runtime: what responsibility it claims, which module would naturally import it, and whether it is obsolete, half-integrated, or types-only.
- Delete genuinely unused code.
- Wire required runtime behavior through the module that owns it.
- Move a type into its using module when the file has no runtime values.
Avoid:
- Dummy imports, barrel exports or other synthetic edges solely for reachability.
- Side-effect imports unless the side effect is required runtime behavior.
- Renaming/relocating a file merely to exploit structural-root detection.
- Keeping obsolete code "just in case".
- Treating an `import type` referrer as keeping a module alive.
Unless:
- `index.ts`/`index.tsx` are structural (like `__init__.py`), never reported.
- Test files are entrypoints, excluded.
- A scan root with no structural root is skipped.
Why: An unreachable file signals unclear ownership or incomplete integration, not a request to manufacture an edge; repair by removing code with no runtime responsibility or connecting it through its real owner.
