Title: Give each journey spec well-formed test URNs naming its own subject
Given: A browser spec: a `*.e2e.ts` file run by Playwright, or any test file whose header comments carry a journey marker (`// Train:`, `// Journey:`, `// URN: test:train:…`, `// URN: test:journey:…`).
When: The spec is written or changed.
Then: It carries at least one test URN `test:{train|journey}:<id>:{E2E|SMOKE|A11Y|VIS|RESP}-NNN-<slug>`, and every URN it carries is well-formed and names the subject its binding header declares.
Prefer:
- Same URN in header and test title, e.g. `test:train:orders:place-order:E2E-001-places-an-order`.
- The harness code matching what the test exercises.
Avoid:
- Malformed URNs (wrong prefix, unknown harness code, missing NNN or slug).
- URNs naming a different train/journey than this spec's binding.
- Renaming a spec away from `*.e2e.ts` to dodge the check; header markers still apply.
Unless:
- Vendored or generated tree (`node_modules`, `dist`, `build`, `_generated`).
- Malformed binding header: no URN-vs-binding comparison; `tester.htmx.journey-binding-header` alone reports it.
Why: The URN identifies the test instance and its harness. A malformed URN, or one naming another subject, silently traces the result to the wrong place.
