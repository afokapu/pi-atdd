Title: Accept a delivery only on a read-only, candidate-bound, synthetic owner-inspection record
Given: A delivery Flow tracks with an owner-inspection/v1 record that Flow owns and publishes and that Flow has already read (consumed by Bun via the exact-pinned @afokapu/atdd-flow type). Flow exclusively owns acknowledgement, which may still be missing; an unacknowledged record is in scope and must be checked.
When: The delivery is about to be accepted or marked done for a candidate commit.
Then: Accept only if the record fits that exact candidate: published for its commit, tracked evidence digests matching, target a credential-free 127.0.0.1 or localhost URL, data_classification exactly `synthetic`, both a teardown reference and its digest present, N/A only for a toolkit surface with rationale and a Flow-defined direct evidence kind, and operator@desk acknowledgement before done.
Prefer:
- Report FAIL when any finding applies; report COULD_NOT_CHECK for evidence that is not a tracked path (e.g. a CI run URL) or a tracked path that cannot be read; PASS only when no finding applies and every evidence reference was verified against tracked bytes.
- Require republishing through Flow when the candidate or an evidence file changed.
- Require only synthetic data, a credential-free 127.0.0.1/localhost target, and recorded teardown evidence (reference + digest).
- Confirm the record is read only via the exact-pinned @afokapu/atdd-flow type; treat `synthetic` as Bun applicability policy, not a Flow schema constraint (Flow's field is free text).
Avoid:
- Editing, writing, publishing, storing or copying the record into Bun state, or creating parallel manifest/registry/schema/report/preview/acknowledgement/dependency state; Flow alone owns its shape, publication, acknowledgement and cleanup lifecycle, Bun only reports findings.
- Production targets, deploys, implicit previews or fabricated URLs; sandbox/preview targets without explicit authorization of owner directive M-20261011T121147Z.
- Promoting COULD_NOT_CHECK (untracked or unreadable evidence) to PASS.
- Skipping the check for a record because it is not yet acknowledged.
Unless:
- A toolkit repository with no served surface states rendered N/A with an exact rationale and direct evidence of a Flow-defined N/A kind (CI run, gate report, or package listing); it is never given a fabricated URL.
Why: Owner inspection proves a delivery only if this exact candidate was inspected safely and the owner saw it; Bun reading, not writing, keeps Flow the single source of truth.
