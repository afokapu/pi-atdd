Title: Resolve every wagon artifact URN to a registered contract
Given: A wagon declares artifact URNs (e.g. contract:<domain>:<name>), whether new or existing, and a contract registry exists.
When: You check, validate, plan or change wagons, their artifacts or the contract registry.
Then: Ensure every wagon artifact URN resolves to a matching contract in the registry (e.g. contract:<domain>:<name> -> <domain>:<name>:v*); any unresolved URN is an orphan and a violation.
Prefer:
- Validate that all wagon URNs resolve to registry contracts first (migration phase2), then generate the missing contracts for any orphaned URNs (migration phase3).
- Treat orphan detection output as a work list of contracts to create, so each artifact gets a defined schema, version and API.
- Check every wagon artifact URN, not only contract:<domain>:<name> ones; if you cannot establish how a URN form maps to a registry id, report it as unresolved rather than skipping it.
Avoid:
- Leaving any wagon artifact URN that names no contract in the registry (e.g. contract:ux:phantom with no ux:phantom:v* id), including pre-existing ones.
- Removing or renaming a registry contract when it leaves a wagon URN with no remaining matching contract.
Why: URNs are the bidirectional link between wagon artifacts and contracts; a URN that resolves to no contract breaks that link and leaves the artifact's schema, version and API undefined.
