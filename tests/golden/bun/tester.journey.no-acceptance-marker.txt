Title: Keep Acceptance and WMBT headers out of journey specs
Given: A journey spec: a browser spec that is not a bun test file — a `*.e2e.*` file run by Playwright, or a Playwright/test file bound to a train or journey via header comments (`// Train:`, `// Journey:`, `// URN: test:train:…`, `// URN: test:journey:…`). Bun test files are never journey specs.
When: the spec is written or edited
Then: The journey spec MUST NOT carry `// Acceptance:` or `// WMBT:` header lines.
Prefer:
- Move acceptance assertions out of the journey spec into an acceptance test that declares the Acceptance/WMBT pair.
- Or simply drop the `// Acceptance:`/`// WMBT:` lines and keep the spec bound only to its train or journey.
Avoid:
- Giving one test both a journey identity (train/journey) and an acceptance identity (Acceptance/WMBT).
- Renaming a journey spec away from `*.e2e.*` to escape the check while it keeps a journey marker — misnamed specs are still judged.
- Treating a bun test file as a journey spec.
Unless:
- Vendored and generated trees (`node_modules`, `dist`, `build`, `_generated`) are never scanned.
Why: Journey and acceptance identities are exclusive: a journey test binds to a train or journey, an acceptance test to an Acceptance/WMBT pair. Carrying both makes the test ambiguous about what it proves.
