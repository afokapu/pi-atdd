Title: Declare a harness type for each acceptance criterion
Given: An acceptance criterion exists in a plan or acceptance artifact being authored, edited or assessed
When: The planner writes, revises or reviews that acceptance criterion
Then: Ensure the criterion declares a harness type: the test layer that exercises the acceptance, as a code from the harness vocabulary (e.g. UNIT, INTEGRATION, HTTP, E2E, SMOKE).
Prefer:
- Pick the harness code naming the test layer that actually exercises the acceptance, e.g. UNIT, INTEGRATION, HTTP, E2E, SMOKE.
- Use only codes defined in the harness vocabulary.
Avoid:
- Free-text or non-vocabulary harness labels such as 'functional' or 'manual'.
- Leaving the harness implicit or undeclared on any acceptance criterion, including pre-existing ones you edit or review.
Why: The harness tells downstream agents which test layer must exercise the acceptance; without a declared vocabulary code the acceptance cannot be routed to, or proven by, a concrete test.
