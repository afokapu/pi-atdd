Title: Declare every docs/ path the change touches, by exact path
Given: A plan's work has a recorded documentation declaration, and core supplies its change set.
When: that change set is evaluated.
Then: Every added, modified or deleted path under docs/ (outside docs/dist/) exactly equals some declared artifact's `path` or some `archive` artifact's `from`.
Prefer:
- Declare exact paths at RATIFY, before the work: `documentation: {impact: change, artifacts: [{action: modify, path: docs/purpose/release.adoc}]}`.
- To remove a document, declare an `archive` artifact whose `from` is the removed path. Removing a document is a documentation change.
- If an unplanned change IS a documentation change, the declaration was wrong at RATIFY. Re-ratify.
Avoid:
- Widening the declaration to absorb a change that is not a documentation change, such as a typo fix in a rendered artefact or a path you did not mean to touch. Do not touch docs/ instead.
- Relying on a prefix or glob to cover files. Coverage is exact-path only.
Unless:
- Paths in docs/dist/** never need to be declared. They are generated output: a rendered site changing is a consequence of an authored change, and requiring it would make every declaration carry generated paths.
- No declaration is recorded at all. That case belongs to core, not to this rule.
Why: Deciding whether a change SHOULD have been declared is semantic and cannot be done deterministically. Detecting that a declared-docs repo touched docs/ without declaring it can be, and it catches the same drift from the other side. Core checks that declared paths were touched, and this part checks that touched paths were declared. Neither check closes the loop alone.
