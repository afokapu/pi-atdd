Title: URN layer must match the file's real architectural responsibility
Given: A file declares a six-segment URN; segment 5 is the layer the boundary and dependency-flow rules read to judge imports.
When: You choose or change the URN layer, or its layer does not match what the file actually does.
Then: Pick the one of `domain`, `application`, `integration`, `presentation`, `assembly` that matches the file's real responsibility.
Prefer:
- During GREEN: derive the layer from the existing architecture and the responsibility the current acceptance requires.
- During GREEN: follow the nearest existing compliant feature pattern.
- During GREEN: if the file is actually misplaced, move only the affected implementation to its proper layer.
Avoid:
- Relabelling a misplaced module to make dependency checks disappear.
- Reorganizing adjacent features.
Unless:
- The URN is not six segments; it is skipped.
Why: Layering rules read segment 5 to decide whether an import is legal. With a wrong layer, those rules check the file's imports against the wrong boundary.
