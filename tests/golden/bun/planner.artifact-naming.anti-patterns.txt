Title: Avoid the catalogued artifact-naming anti-patterns
Given: A plan, wagon, WMBT, acceptance or doc you author or review declares, uses or references artifact names
When: You write, rename, use or review an artifact name
Then: The artifact name matches none of the catalogued anti-patterns.
Prefer:
- Colons between hierarchy levels; a dot only before a variant
- Always lead with the theme
- Name only the public artifact; internals stay internal
- Only hierarchy levels that add distinction; a specific aspect
Avoid:
- wrong_separator_for_hierarchy: commons:ux.foundations.color -> commons:ux:foundations:color
- wrong_separator_for_variant: sensory:gesture:raw -> sensory:gesture.raw
- missing_theme: gesture.raw -> sensory:gesture.raw
- too_many_dots: commons:identifiers.uuid.v7.timestamp.encoded -> commons:identifiers.uuid
- unnecessary_hierarchy: match:config:base:standard -> match:config
- generic_aspect: match:data -> match:state.committed
- theme_in_aspect: sensory:sensory-feedback.visual -> sensory:feedback.visual
Why: Artifact names are contract keys between wagons; these forms break the theme:aspect.variant grammar, leak internals, or make names vague or duplicative.
