Title: Use only registry-declared kebab-case themes on plan-namespace artifacts and contracts
Given: A plan artifact or contract uses the repository plan theme namespace (theme field or theme-prefixed identity), or plan/_themes.yaml is involved.
When: You author, edit or review such an artifact, contract or the theme registry.
Then: Every declared theme must be a value in the repository registry plan/_themes.yaml (registry membership).
Prefer:
- Add the theme to plan/_themes.yaml before any artifact or contract references it.
- Required: theme names are kebab-case matching ^[a-z][a-z0-9-]*$.
- Required: registry index 0 is commons, the only reserved entry; the repository declares every other theme.
- Required: the first segment of every artifact or contract identity equals its declared theme.
Avoid:
- Declaring a theme absent from plan/_themes.yaml.
- Theme names with uppercase, underscores, spaces or leading digits/hyphens.
- Removing, renaming or moving commons off index 0, or reserving another entry.
- An identity whose first segment differs from its theme.
Why: A theme is a repository-defined namespace for plan artifacts; registry membership and identity-prefix consistency are what make it enforceable.
