Title: Group WMBTs into cohesive features by a named grouping strategy
Given: WMBTs that belong, or are being placed, in a user-facing feature.
When: The planner creates, fills, regroups, or changes the meaning of a feature or its WMBTs.
Then: Group the feature's WMBTs by shared JTBD step, shared measured dimension, shared controlled object, or a coherent user story (any of these strategies, possibly several at once), with at most 10 WMBTs per group.
Prefer:
- by_step: WMBTs that share the same JTBD step (<=10).
- by_dimension: WMBTs that measure the same dimension (<=10).
- by_object: WMBTs that control the same object (<=10).
- by_coherence: WMBTs that form a coherent user story (<=10).
- Use cues to find a coherent grouping: shared object of control, shared metric kind, shared plane/domain, same user story/flow.
- Keep every feature user-facing and cohesive.
Avoid:
- Miscellaneous / catch-all buckets of unrelated WMBTs.
- Groups exceeding 10 WMBTs.
- Features that are not user-facing.
Why: Cohesive, user-facing features of bounded size keep acceptance scope reviewable and keep the feature within its size budget; miscellaneous buckets hide unrelated work and break cohesion.
