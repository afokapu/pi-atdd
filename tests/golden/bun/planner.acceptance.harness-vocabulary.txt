Title: Use only the authoritative harness names and UPPERCASE codes
Given: Any acceptance, criterion, URN, test or doc that names a harness or harness code.
When: A harness name or code is written, chosen, generated, read or mapped.
Then: Use a harness name from the authoritative vocabulary and exactly its UPPERCASE code from the code map.
Prefer:
- Valid names: unit, http, event, ws, e2e, a11y, visual, metric, job, db, sec, load, script, widget, golden, bloc, integration, rls, edge_function, realtime, storage, smoke. Code = name in UPPERCASE, except visual->VIS, edge_function->EDGE.
- Pick a harness whose typical layers include the layer under test: domain: unit; application: unit, http, event, metric, job, sec, script, golden, bloc; integration: http, event, ws, metric, db, sec, load, integration, rls, edge_function, realtime, storage; presentation: e2e, a11y, visual, widget, golden. smoke has no layer entry.
Avoid:
- Invented names or codes, lowercase or variant codes (VISUAL, EDGE_FUNCTION).
- A harness whose typical layers exclude the tested layer, without justification.
Why: The vocabulary is authoritative: URNs embed the UPPERCASE code and criteria templates share the harness set, so non-canonical names/codes break URN generation and harness lookup.
