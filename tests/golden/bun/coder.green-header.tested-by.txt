Title: Bind every implementation file to at least one acceptance via Tested-By
Given: Any implementation (non-test) source file — new, modified, or untouched
When: It exists in the repository (continuous obligation, not only when the header is edited)
Then: The header MUST contain a `Tested-By:` line followed by at least one `- test:` entry, each naming a real, exactly-declared acceptance URN that exercises the file; an empty block counts as absent.
Prefer:
- During GREEN, derive the binding from the acceptance being implemented.
- Keep existing valid bindings; add only the acceptance that genuinely covers this file.
- Use the exact declared acceptance URN.
- One entry suffices; more are encouraged when they genuinely cover the file.
- Pick the acceptance whose scenario drives code in this file (check its behavior, not just its name).
- Prove the binding by running the behavioral acceptance named in the `Tested-By:` header and confirming it passes.
Avoid:
- Inventing acceptance IDs.
- Adding unrelated tests merely to make the block non-empty.
- Claiming coverage from an acceptance that does not exercise the implementation.
- Leaving a bare `Tested-By:` line with no entries.
Unless:
- The file is a test file — the other end of this binding.
Why: The URN says what the file IS; `Tested-By:` says what PROVES it, closing the acceptance-to-implementation loop that stack migrations silently break. An empty block (half-finished backfill) would report full coverage with zero bindings.
