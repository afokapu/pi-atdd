Title: Declare every theme in the repository's plan/_themes.yaml
Given: A plan has plan/_themes.yaml and/or wagons, trains, interlockings, or contracts with a theme (new, changed, or unchanged); registry-only work included.
When: The planner authors, edits, or validates a themed plan artifact or the registry.
Then: Every wagon, train, interlocking, and contract theme MUST resolve to a value in the repository-owned plan/_themes.yaml registry.
Prefer:
- Declare themes in plan/_themes.yaml with any kebab-case name.
- Keep index 0 reserved for commons: if index 0 is populated, its name is commons.
- Treat an unresolved theme as a plan error; fix the registry or the artifact.
- Check all of: index 0, if populated, is commons; names are kebab-case; every artifact theme resolves. Resolution alone is not compliance.
Avoid:
- Relying on a package default taxonomy; none exists, and no game or toolkit vocabulary is supplied.
- Expecting a package-default lookup to resolve an undeclared theme.
- Any name other than commons at index 0.
- Non-kebab-case theme names.
Why: Themes are repository-owned with no package fallback, so an undeclared theme is a plan error. Downstream naming and boundary rules presuppose a resolvable theme.
