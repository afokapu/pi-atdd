Title: Point every doc relationship at a declared doc-id
Given: An authored .adoc corpus whose documents carry relationship attributes (`:decides:`, `:supersedes:`, `:implements:`, `:depends-on:`).
When: You add or change such an attribute, edit a document that has one, or delete a document or change a `:doc-id:` that other documents may name.
Then: Every relationship attribute MUST name a doc-id that some document in the corpus actually declares in its `:doc-id:`.
Prefer:
- Either declare the target, or fix the reference: `:implements: purpose.worktrees` resolves, while `purpose.wortrees` (a typo) is REPORTED.
- If the target does not exist yet, the reference is premature. Author the target document first.
- Use only the four shipped verbs: `decides`, `supersedes`, `implements`, `depends-on`.
Avoid:
- Edges to a document you only intend to write. To every reader and every tool, they look the same as edges to a deleted document.
- `refines`. It is deliberately not shipped (spec 2 §9 Decision 3).
Unless:
- An absent attribute is not an unresolved edge. Only declared relationships are resolved.
Why: Resolve or report, never invent. A target outside the declared-id set is a REPORTED finding, never a synthesized node. This is the one hard requirement of spec 2 §5.4.
