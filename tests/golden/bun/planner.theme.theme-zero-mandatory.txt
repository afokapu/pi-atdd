Title: Keep commons at theme index 0 in plan/_themes.yaml
Given: A repository's theme map plan/_themes.yaml (the resolved theme set) is authoritative and repository-owned; its only package-supplied entry is commons at index 0.
When: plan/_themes.yaml is created, edited, reordered, deleted or validated, by any actor, whether or not index 0 is touched.
Then: plan/_themes.yaml MUST declare commons at theme index 0.
Prefer:
- Add repository-specific themes at any other (non-zero) index, as long as each is a valid theme.
- Ensure the end state has index 0 exactly 'commons' — keep it there, or repair the map so it becomes commons if it is currently missing or wrong.
Avoid:
- Replacing commons at index 0 with a repository-specific theme.
- Removing the commons floor, leaving index 0 empty, or deleting the theme map file.
- Moving commons to a different index or shifting another theme into digit 0.
- Adding other package-supplied entries to the map beyond the required index-0 commons.
Why: Commons at digit 0 is the mandatory, non-removable floor of every theme set; the rest of the map is owned by the repository and may be extended freely.
