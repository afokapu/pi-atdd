Title: Bind emitting source to its tracking-plan item with a resolving Telemetry: header
Given: In a telemetry-adopting repository, non-test source emits telemetry or carries a `// Telemetry:` line comment.
When: The source is written, edited or checked, or the tracking plan renames/removes an item.
Then: Each emitted item is declared by name in a `// Telemetry:` header, and every header names a concrete URN `telemetry:{kind}:{plane}:{theme}:{artifact}[:{measure}]` matching a JSON tracking-plan item id under telemetry/<theme>/<artifact>/.
Prefer:
- `//` header above the emitting code, e.g. `// Telemetry: telemetry:event:be:commons:response-invocation-accepted`.
- One header per emitted item.
- Update headers in the same change when the plan renames.
Avoid:
- Emitting telemetry with no header.
- Non-concrete URNs (missing parts, wildcards, placeholders).
- URNs naming no plan item, incl. stale after rename.
- Block comments, markup attributes, string literals as headers.
- Naming an item the file does not emit just to resolve.
Unless:
- Not adopted (no telemetry root, no acceptance telemetry declaration anywhere): nothing emitted, whichever profiles run.
- Test files: they legitimately name items while asserting them.
Why: The header is the source-to-telemetry traceability edge; like Tested-By, a checkable promise: the URN is well-formed and the registry holds it.
