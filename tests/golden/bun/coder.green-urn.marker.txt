Title: Open every implementation file with its component URN marker
Given: A Bun/htmx implementation file (.ts, .tsx, .js, .jsx, .mjs, .mts, .html/.htm template) outside test files and vendored/generated trees
When: the file exists in scope (new, edited or pre-existing)
Then: Its first meaningful line MUST be a `URN: component:…` marker — `// URN:` in source, `<!-- URN: … -->` in a template — after only blank lines and an allowed shebang or HTML doctype.
Prefer:
- During GREEN: derive the URN from the plan ownership of the implementation being added.
- During GREEN: use `//` syntax for code and `<!-- … -->` for templates.
- During GREEN: add only the marker; don't restructure a correctly placed file.
Avoid:
- Marker below imports or any content (reads as MISSING).
- Inventing a wagon, feature, component, side, or layer.
- Copying a nearby file's URN without verifying ownership.
- Moving code merely to make the marker easier to write.
Unless:
- Test files (`*.test.*`, `*.spec.*`): bound by their acceptance URNs instead.
- Vendored/generated trees (`node_modules`, `dist`, `build`, `_generated`): never scanned.
- A shebang or `<!doctype>` may precede the marker.
Why: The URN is the only edge between a source file and the plan graph; without it no acceptance can claim the file, no wagon owns it, and coverage cannot see it exists.
