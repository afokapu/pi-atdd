Title: Make every typed plan reference resolve to a declared artifact
Given: The plan contains typed references (`wagon:`, `feature:`, `wmbt:`, `train:`, `interlocking:`, `journey:`) in its artifacts, changed or not.
When: The plan is validated or inspected as a whole, or the planner authors, edits, removes or renames plan artifacts.
Then: Every such typed reference must name an artifact the plan declares.
Prefer:
- Declare the referenced artifact in the plan when the relationship is real.
- Correct the reference to the actual declared id when it is a typo or stale after a rename.
- When removing or renaming an artifact, update every typed reference that points to it in the same change.
Avoid:
- Leaving references to nothing — a relationship the plan claims but cannot show.
- Creating empty placeholder artifacts only to make a reference resolve without the relationship being real.
- Treating `contract:` references under this rule; they belong to the contract registry rules.
Unless:
- The reference lives in a vendored or generated tree (`node_modules`, `dist`, `build`, `_generated`); those are never scanned.
Why: A reference to nothing is a relationship the plan claims and cannot show; unresolved references break plan traceability.
