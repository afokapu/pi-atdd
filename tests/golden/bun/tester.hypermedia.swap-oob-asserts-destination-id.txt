Title: Out-of-band swap tests assert the destination id
Given: A test case whose body mentions `hx-swap-oob`, e.g. asserting an out-of-band swap is present in a response
When: the test case is present in the suite (new, changed or existing)
Then: The same test case MUST also assert the destination `id` the out-of-band element will be matched against.
Prefer:
- Assert the destination, not just the mechanism: `expect(html).toContain("hx-swap-oob"); // the server's half only` then `expect(html).toContain('id="cart-count"'); // the half that must match the page`.
- Any id-reaching assertion works; no specific matcher is required.
- Bind the runtime-artefact assertion back to the declaration it came from: the id the page declares.
Avoid:
- Half assertions: checking `hx-swap-oob` appears and stopping — proves only the server's half, not the destination a template refactor breaks.
- An id assertion unrelated to the oob element's destination, just to satisfy the detector.
Unless:
- The test case never mentions `hx-swap-oob` (out of scope).
Why: htmx silently drops an oob element whose id matches nothing in the document (no error, no warning, no swap); the id must be in the response AND the document. The coder rule makes the server emit an id; only this rule makes a test prove it is the id the page will match.
