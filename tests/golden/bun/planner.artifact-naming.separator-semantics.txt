Title: Use colon for hierarchy and dot for variant in artifact names
Given: An artifact name whose colon (:) and dot (.) separators carry meaning
When: the artifact name is chosen, referenced or reviewed
Then: Use colon (:) only for hierarchical descent to a deeper conceptual level, and dot (.) only for a lateral variation (flavor/state) of the same thing.
Prefer:
- Colon for each step deeper into the resource tree; depth is unlimited (e.g. commons:ux:foundations:color, scenario:catalog:primitives:actor).
- Keep dots shallow: typically one dot suffix for a variant of the same artifact (e.g. sensory:gesture.raw, player:session.active, match:config.duel), rarely two.
Avoid:
- Chaining multiple dots (e.g. .uuid.v7.encoded) — this usually signals over-specification.
- Using a dot to express a deeper conceptual level, or a colon to express a mere flavor/state of the same thing.
Why: Colon is a strong boundary between different conceptual levels; dot is a soft boundary between facets at the same level. Keeping them distinct makes names navigable as a tree and keeps variants shallow.
