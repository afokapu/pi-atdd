Title: Declare what every URN-carrying test proves
Given: A test file carries a URN identity header
When: The test is written, changed or reviewed
Then: Declare beside the URN the plan obligation the test actually proves: `// Acceptance: acc:…`, or `// Train: …` only for a journey/E2E test.
Prefer:
- Derive the binding from the plan artifact the test proves: the declared acceptance whose behavior the file exercises and asserts, or the declared train the journey actually walks
- Use that exact plan identity: `// Acceptance: acc:<domain>:<acceptance-id>` or `// Train: train:<domain>:<journey>`
Avoid:
- Picking any resolvable acceptance merely to satisfy coverage
- Changing the claimed binding to match a test that proves different behavior (rebinding for attribution); correcting a stale binding to the obligation the test truly proves is the fix, not this
- Selecting or inventing a binding (new acceptance or train) merely to make an orphaned test bind or be attributable
Unless:
- A `Train:` binding satisfies the rule for journey and E2E tests, when the journey actually proves that train
Why: A URN says which test this is; the binding says which obligation it discharges, and only that closes the loop the gate reads. The binding is a claim: truthful only if the test exercises the declared subject and asserts its outcome. A convenient but unrelated resolvable acceptance creates false coverage while still passing the structural detector. Train bindings exist because journeys prove a train; forcing an acceptance would push authors to invent linter-only acceptances that pollute the plan graph.
