Title: Derive feature names from produce/consume artifacts as {verb}-{domain|resource}
Given: A feature produces/consumes artifacts (WHAT: entities, states, events); features are HOW (actions, capabilities).
When: You derive, add, rename or review the feature's name.
Then: Name it {verb}-{domain} if it acts on the entire domain, {verb}-{resource} if on a specific resource within the domain; choose the verb by artifact type (event, state, data, config).
Prefer:
- Typical verbs (not closed lists): events (past tense: ended, started, closed) → publish, emit, start, close, trigger; states (adjectives: remaining, active, current) → track, monitor, maintain, update; data (nouns: choice, identity, profile) → create, manage, process, handle, make; configs (config, settings, agreement) → configure, setup, initialize, define.
- Another verb that fits better is fine, e.g. the verb form of the artifact (identity → identify-<domain>).
- Identify domain and resource from the artifact's meaning; in a nested name the domain is not necessarily the part before the colon.
Avoid:
- Naming the feature after the artifact (WHAT) instead of an action (HOW) on it.
- A verb that does not fit the artifact's type and meaning.
- Resource as object when the feature acts on the whole domain, or domain when it targets one resource.
Why: A consistent WHAT→HOW transformation makes feature names derivable from artifacts so the plan stays coherent.
