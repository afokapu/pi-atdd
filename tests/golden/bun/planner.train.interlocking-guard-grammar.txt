Title: Write interlocking guards only in the declarative guard grammar
Given: A train interlocking declares guard expressions
When: the planner writes or edits a guard, or the plan reaches CONFIRM
Then: Every guard uses only the guard grammar. Inputs: action/request inputs, an explicit state snapshot, and a completed TrainResult only at declared route boundaries. Operators: == != < <= > >= and or not exists(field) in.
Prefer:
- Pure comparisons and boolean combinations over declared input and snapshot fields.
- exists(field) to test whether a field is present.
- Pass needed data through the explicit state snapshot.
Avoid:
- Raw Python eval or arbitrary executable code: calls other than exists(field), imports, lambdas, method calls, comprehensions. Plain references to allowed input fields are fine.
- Side effects or non-deterministic inputs (time, randomness, environment, I/O).
- Reading a TrainResult that is not completed or is outside a declared route boundary.
- Disguising disallowed tokens to get past the validator.
Why: Guards decide routing. Declarative, deterministic, side-effect-free guards keep routes reproducible and statically checkable. Raw eval allows arbitrary code execution.
