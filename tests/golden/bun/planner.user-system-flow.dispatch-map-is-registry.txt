Title: Keep the divergence dispatch map a declared, schema-valid registry
Given: Work plans, implements, changes, or checks how the Station Master routes produced-artifact divergence to trains.
When: The divergence dispatch map is specified, built, modified, or reviewed.
Then: The divergence dispatch map itself must be a declared, schema-valid registry (artifact_urn -> train_id) that the Station Master actually reads; routing must never be an imperative in-code map.
Prefer:
- Before planning, locate the repository's existing dispatch registry, its schema and its validator test, and plan changes there. Do not invent a new location or schema.
- Plan routing changes as registry entries keyed by artifact_urn mapping to train_id, validated against the registry schema.
- Write acceptances that assert the Station Master resolves routes by reading the registry. A plan-only registry paired with an in-code implementation must then fail.
Avoid:
- Routing as a hard-coded map, switch or conditional chain in Station Master code, whether planned or already present.
- Registry entries that bypass or fail schema validation.
- Treating a registry described only in the plan as compliance when the Station Master does not read it.
Why: The source requires divergence routing to be a declared, schema-valid registry that the Station Master reads, not an imperative in-code map.
