Title: Every htmx endpoint declared in markup has a test
Given: A scan mount containing test files and markup declaring endpoints via htmx verb attributes (hx-get, hx-post, hx-put, hx-patch, hx-delete)
When: The mount is scanned: every declared hx- verb endpoint, changed or not, is checked against the mount's tests
Then: Every endpoint declared by an htmx verb attribute MUST be exercised by at least one test in the same mount.
Prefer:
- Write a test exercising the endpoint: `<div hx-get="/invoices/overdue" hx-target="#late"></div>` (declared) is covered by `const res = await fetch("/invoices/overdue"); expect(res.status).toBe(200);` (exercised).
- If the surface is not real, delete the hx- attribute instead.
- Read the markup as the route space: the hx- attribute IS the request.
Avoid:
- Adding an hx- verb attribute with no test, so a new server surface exists that nothing records.
- Reporting endpoints uncovered on a source-only mount.
Unless:
- The mount contains no test files: skip it entirely.
- A dynamic segment matches on its static prefix (`/orders/1` covers `/orders/:id`).
- Absolute-URL endpoints are `coder.htmx.verb-endpoint-same-origin`'s finding.
Why: An htmx endpoint is an element attribute, not an enumerable router-table entry, so the route space grows and is forgotten easily; this rule notices new surfaces. A coverage claim needs a suite to measure against, so without tests it stays silent.
