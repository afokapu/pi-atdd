Title: Declare the runtime the file executes in
Given: A non-test implementation file in a Bun-stack project, new or existing
When: the file is present in the codebase (created, edited, or untouched) and its runtime declaration is checked
Then: The file MUST carry a `Runtime:` declaration naming where it actually executes: `bun`, `browser`, or `isomorphic`.
Prefer:
- During GREEN: derive the value from the real execution path created or used by the current acceptance (where the module is actually loaded and run), not from file location or hypothetical reuse.
- During GREEN: keep an existing correct runtime declaration.
- During GREEN: change only the header when the implementation already executes in the correct place.
- Use `isomorphic` only for a module that genuinely runs both server-side and in the browser.
Avoid:
- Broadening the fix: moving code between server and browser merely to fit a preferred label.
- Guessing `isomorphic` because the file could theoretically run in both places.
- Picking a wrong single-side value for a module that really runs in both places.
Unless:
- Test files are excluded.
Why: Bun decides at run time what a bundler decides at build time, so a full-stack Bun module can routinely run in both places; without an `isomorphic` value authors would be forced to pick a wrong one and every downstream reader would inherit the error.
