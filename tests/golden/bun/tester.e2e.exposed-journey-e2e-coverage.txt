Title: Bind every exposed frontend journey to an E2E or SMOKE browser spec
Given: A journey has an exposed entrypoint whose `surfaces` include `frontend` or declare none.
When: Always, for every such journey, new or existing (e.g. when the tester writes specs, or a journey is added or its exposure/surfaces change).
Then: At least one browser spec MUST be bound to that journey with `// Journey: <journey id>` and carry an E2E or SMOKE test URN.
Prefer:
- Add `e2e/<journey>.smoke.e2e.ts` bound with `// Journey: <journey id>`.
Avoid:
- Counting a unit test that only mentions the journey URN in a string as coverage; it is not a browser spec and leaves the journey uncovered.
- Relying on route-level tests alone: they prove each routing decision, not that the journey runs end to end in a browser.
- Misnaming a spec to escape judgment: any test file with journey-marker header comments is judged as a browser spec.
Unless:
- The journey is internal, or its exposed entrypoint `surfaces` exclude `frontend` (e.g. `[backend]`): no browser surface, out of scope.
- Files in vendored/generated trees (`node_modules`, `dist`, `build`, `_generated`) are never scanned (they neither are judged nor count as coverage).
Why: An exposed journey is what a user can start. Route-level rules prove each routing decision; this rule proves the journey runs end to end in a browser.
