Title: Exercise every declared timing semantic in a bound telemetry test
Given: In an adopted repository, a tracking-plan item declares timing semantics (post-commit, absent-after-rollback, correlation-across-async) in its timing list
When: The item and its Telemetry:-bound tests are evaluated — on any plan or test change, or for existing unchanged items
Then: For each declared semantic, at least one bound test must reference the behaviour (commit, rollback, correlation/context) in code or a test title.
Prefer:
- Declare on the item, name it in the bound test: "timing": ["post-commit"] with test("emits the planned event once the invocation commits", () => { ... }).
- Assert the behaviour: emission only after commit, none after rollback, context kept across the async handoff.
Avoid:
- Satisfying a semantic only via a test comment or tracking-plan prose.
- Relying on return-value tests for transaction-time telemetry.
- Claiming the lexical check proves ordering statically — false precision.
Unless:
- The item declares no timing (empty timing list, e.g. diagnostic logs, internal spans).
- The rule family is not yet adopted: the rule is inert until adoption.
Why: Transaction-time bugs (event fired before its commit, rollback that still emits, context lost across an await) escape return-value tests; the plan declares when ordering matters, so bound tests must speak to it.
