Title: Migrate v1 artifact names to theme:hierarchy:aspect.variant
Given: A plan, wagon or acceptance uses a legacy v1 artifact name (no theme, or dots for hierarchy).
When: The planner migrates that name to v2.
Then: Rewrite it as theme:hierarchy:aspect.variant — assign a theme, colons between hierarchy levels, dots only before variants — and realign every wagon manifest, feature file, URN, contract file location and $id field that carries it.
Prefer:
- Steps in order: identify names -> determine theme -> identify hierarchy -> separate hierarchy from variants -> update wagon manifests -> update feature files -> update URNs -> reorganize contracts -> update $id fields.
- Templates: identifiers:uuid -> commons:identifiers.uuid; ux.foundations.color -> commons:ux:foundations:color; ux.foundations.color.primary -> commons:ux:foundations:color.primary.
Avoid:
- Renaming only the name while manifests, feature files, URNs, contract layout or $id fields keep the old one.
- Dots between hierarchy levels, or a colon before a variant.
- Migrating without a theme prefix.
Why: Piecemeal migration leaves URNs, manifests and contract $ids pointing at different identities; one form with colons for hierarchy and dots for variants keeps them consistent.
