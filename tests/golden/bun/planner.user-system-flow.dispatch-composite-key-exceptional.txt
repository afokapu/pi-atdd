Title: Admit composite dispatch keys only with a behavioral difference and a single field:value discriminant
Given: A dispatch map routes artifacts to trains, and a composite (artifact_urn, discriminant) -> train_id dispatch key exists or is proposed.
When: That composite dispatch key is introduced, changed or assessed (in a plan, acceptance, doc or review).
Then: Treat the composite key as exceptional: permit it only with a behavioral_difference justification and a discriminant that is exactly one field:value.
Prefer:
- Key dispatch by artifact_urn alone; use a composite key only when there is a behavioral difference to justify it.
- State the behavioral_difference as the observable behavior that differs between the routed trains.
- Write the discriminant as exactly one field:value.
Avoid:
- Composite keys with a missing or empty behavioral_difference justification.
- Discriminants that are not exactly one field:value (e.g. several fields combined, or no field:value at all).
- Composite keys used for organisational convenience where train behavior is the same.
Why: The dispatch map is a registry mapping an artifact to a train by default; unjustified composite keys break that default and hide why one artifact routes to different trains.
